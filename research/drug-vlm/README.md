## 0. 结论与建议

**一句话回答**：可以借鉴，但借鉴的核心不是"让 AI 自己训练模型"，而是**一把固定、防作弊、带统计检验的评测尺子**，加上 agent 在这把尺子下通宵自动调整训练配方。成败取决于评测集、标注和评分规则，而不是模型架构。第一步不是训练，而是用自家文档量出现成工具差在哪里。

**我们的建议**
1. **先建尺子和混合流水线，尽早给下游供数。** 用现成组件（PDF 文本层与美国专利全文 XML——数值以文本为准；美国专利自带的结构文件、OPSIN 名称转结构、许可干净的专用识别模型、零样本 Qwen3-VL-8B 读表、RDKit 做枚举与单位归一）搭一条混合流水线，第 3 周起按[交付物 schema](docs/deliverable_schema.md)供带出处的预填数据，用于化学家复核和数据库补漏；直接拿来建模要等 S2 出口（约第 7 周）。它同时是每个阶段必须超过的基线。
2. **用 Qwen3-VL（2B 做实验、8B 做产品）+ LoRA 自动优化结构识别。** 结构是每条活性记录的连接键，也是端到端损失的主要来源；这一环评测量足够（约 3,400 张裁剪图），适合 autoresearch 式的自动循环。
3. **属性抽取主要靠 schema、词表、确定性校验和标注，自动循环只用在 SAR 读表上。** 表格评测集只有约 140 张表，能检出的最小提升约 6 pp，自动循环在这里杠杆小（6.5 节）。

**三档投入**（后一档建立在前一档的尺子上；即使只做 A，下游也能拿到带置信度、可追溯出处的预填记录，见 schema 第 3 节"最早可用"）

### 0.1 要点详解

1. **移植本质，改造细节。** 原样保留：固定且只读的评测、只有一个可编辑文件、固定预算、一个与输出表示无关的标量、用 git 记录每次实验并且只在确认变好时才把分支往前推、`program.md` 作为写给 agent 的研究章程、NEVER STOP 与简洁性准则。必须改造：评测要**隔离**（上游只靠一句"不许改"来保护 `evaluate_bpb`）；"变好就保留"要**统计化**；评测集分**开发集 / 隐藏确认集 / 封存测试集**三层；预算从"5 分钟墙钟"改为"**每次 800 万训练 token**（约 1.8 万张裁剪图、约 13 分钟训练）"，并从一个一次性构建的**热启动检查点 W0** 出发。
2. **为什么先做结构。** 最好的端到端系统读数值的召回约 0.85，读结构约 0.58，"结构 + 活性"联合召回只有约 0.33；去掉结构模块，三元组 F1 从 0.32 掉到 0.011〔doc-chem-ie F9；data F23〕。72.5% 的活性值在表格里，所以第二步是 SAR 表。
3. **主杠杆是数据，不是架构。** 文献里最大的收益来自：真实数据占比、"所见即所标"的标签（缩写保留为超原子）、由弱到强的增强课程、手性过采样，以及与评测等价定义一致的序列级奖励（最小风险训练；"结构同一性"二值奖励 RL——文献中用的是 Tanimoto = 1，不区分立体异构，本方案改用评分器的结构键，含立体层）。直接对 OCR 型 VLM 做 SMILES 的全参 SFT 是已知的反面案例。
4. **基座与吞吐。** Qwen3-VL-2B-Instruct 做内循环、8B 做长程复核与生产（Apache-2.0；OCRBench 858/896）。一台 8×H100 上 3 张卡训练、1 张卡常驻评测，一晚可检验 60–110 个想法；只有 1 张卡时约 30–35 个（评测也挤在这张卡上）。
5. **评测是成败关键。** 主流公开评分器都有会被爬山 agent 利用的漏洞（缩写全部塌缩成 `*`、单位与关系符被忽略、无效行不计入精确率、只算召回……）。本目录的 `harness/score.py` 经过多轮对抗审查：与输出表示无关、立体严格、缺失与错答同价、处理 Markush/外消旋/金属配合物/复合单位/中英文列头，记录键带实验类型、物种、基质等上下文，并带按专利族 × 种子的层次配对检验。
6. **噪声比上游大一个数量级以上。** 约 3,400 张的开发集上，初筛（1 个新种子 vs 3 个已存种子）的标准误约 0.75 pp，复现（3 vs 3）约 0.63 pp，80% 功效下能可靠检出的最小提升约 1.6 pp（复现）到 1.9 pp（初筛）；一夜上百次初筛里挑最好的，纯噪声也能"找到"约 1.9 pp。因此只有通过"初筛 → 三种子复现 → 隐藏确认集"的改动才推进分支，并用安慰剂实验实测误保留率。**所以真正被保留的改动会很少——这是不被噪声骗的代价。**
7. **现实预期。** 真实文献单分子识别：最强系统约 93%（MinerU.Chem，仅在线服务），前沿闭源 VLM 65–75%；开源通用 VLM 零样本参差不齐（InternVL3.5 在修订版 MolRecBench-Wild 上 SMILES 39.80，接近 DECIMER，但图级只有 3.05）；小 VLM + LoRA 已在 Markush 上做到最好（MarkushGlyph，2B）。文档级"结构—活性—靶点"三元组 F1 只有约 0.32——**这正是空白和价值所在**。调研时在 awesome-autoresearch 列表里没有发现针对化学结构识别或专利化学数据抽取的衍生项目。
8. **端到端还是模块化。** 证据指向"模块内端到端、模块间解耦并保留出处"，R 基团枚举交给 RDKit。"VLM 能否胜任结构识别"留作可检验的假设：11 月 13 日的 S1 关口上，若 8B 模型在封存的真实文献切片上落后最好的商用许可专用模型 > [5] pp、且当前最优分数每周提升 < [1] pp 连续两周，就让专用模型负责结构识别，VLM 循环转攻读表与关联。两条推理期捷径（美国专利随附的 MOL/CDX 结构文件；OPSIN 把英文 IUPAC 名转成结构）只覆盖美国专利和英文名称。
9. **许可要提前定。** 商用只用 USPTO 专利数据、PubChem 渲染（ChEMBL 是 CC BY-SA 3.0，用于训练商用模型是否触发相同方式共享尚无定论，待法务）、CC BY 的 Markush 数据、Stereo-200k（Apache-2.0）与自有标注；MolParser-7M/MolGallery 是非商用；MarkushGrapher-2、MarkushGlyph 的权重虽是 Apache-2.0，但训练用过非商用数据，**放在研究轨道，不进入商用模型**。

## 1. autoresearch 范式拆解：哪些是本质，哪些是偶然

| # | 设计要素 | autoresearch 中的实现 | 它解决的问题 | 移植时必须保留的"本质" |
|---|---|---|---|---|
| 1 | 固定、只读的评测 | `prepare.py::evaluate_bpb`，固定验证分片、固定 `EVAL_TOKENS`、固定 `MAX_SEQ_LEN` | agent 不能"改尺子"；所有实验用同一把尺子 | 评测代码 + 评测集 + 推理引擎全部冻结、只读、可校验哈希；agent 只能通过受限的 `infer_config` 改提示词、输出格式、分辨率与解码方式 |
| 2 | 单一可编辑文件 | 只改 `train.py` | 搜索空间可控、diff 可审、回滚便宜 | 一个 `train.py`（数据配方、增强、标签视图、LoRA、优化器、损失、输出格式），其余只读 |
| 3 | 固定预算 | `TIME_BUDGET=300s`，不含编译 | 实验可比；吞吐可预期（约 12 次/小时） | 固定**训练 token 预算**（每次 800 万）+ 墙钟硬上限；推理开销由评测解码上限和部署成本否决约束 |
| 4 | 单一标量指标 | `val_bpb`，与词表无关 | 明确的爬山方向；架构/分词器改动可公平比较 | S1 用 `val_struct`（严格结构 F1，按来源加权），S2 用结构 F1 与记录 F1 的复合分；对输出表示不敏感——先标准化成分子再比较，相当于 bpb 的"词表无关性" |
| 5 | git 即实验账本 | 先 commit 再跑；变好就推进分支，否则 `git reset` | 永远站在当前最优点上；可追溯 | 保留，但分支只由 runner 推进；`results.tsv` 不入库 |
| 6 | 贪心爬山 | 严格变好才保留 | 简单、无需人工 | **需要改造**：VLM 微调的评测是离散、小样本、带种子噪声的，需"显著性门控"而非"数值更小即保留" |
| 7 | 简洁性准则 | 小收益 + 丑代码 = 拒；同效果 + 删代码 = 收 | 防止代码熵增 | 保留并量化：净删 ≥ 20 行走"非劣效"路径；净增 > 60 行时增量门槛翻倍 |
| 8 | 自治与容错 | NEVER STOP、10 分钟超时、崩溃自修 | 过夜跑约 100 次 | 保留；训练墙钟硬上限 1,500 秒，崩溃最多自修 2 次 |
| 9 | `program.md` = 写给 agent 的研究章程 | 人只改 Markdown | 人类杠杆点从"写代码"变成"写研究方针" | 保留，并注入领域知识（错误类型、想法先验、禁区）；人类每天在"当前方针"（agent 只读的独立文件）里写 2–5 句话 |
| 10 | 不许加依赖 | 只能用 `pyproject.toml` 里的包 | 环境稳定、防作弊 | 预先锁定 VLM 栈（transformers/peft/trl/vllm/rdkit 等） |
| 11 | 进度可视化 | `analysis.ipynb` 画当前最优曲线 | 人醒来能一眼看懂 | 扩展：主分数 + 分组曲线、种子散点、安慰剂通过率 |

### 1.1 两个场景的根本差异

1. **从零预训练 vs 微调已有 VLM**：autoresearch 的模型几秒钟就能初始化，5 分钟足够看到差异；VLM 实验每次有约 1–2 分钟的固定开销（载入模型、解码图片、启动推理引擎）〔vlm-ft Implications〕，而从热启动点出发，学习率、增强这类改动需要几千步才能显出差异，5 分钟预算过短。
2. **评测成本**：`val_bpb` 是 teacher-forcing 下的一次前向；结构/属性抽取必须**自回归生成**再解析，评测是主要开销之一，必须固定推理引擎与解码参数。
3. **指标性质**：bpb 连续、低噪声、样本量极大（约 2,000 万 token）；抽取精度是离散的精确匹配，评测集通常只有几千个样本，标准误不可忽略。
4. **主要杠杆**：预训练的主杠杆是架构/优化器；微调抽取任务的主杠杆是**数据**（合成渲染、增强、真实数据配比、输出格式、课程）、分辨率、LoRA 配置与 RL 奖励。
5. **过拟合开发集的风险**：一夜几十上百次实验都在同一个开发集上挑最优，存在"赢家诅咒"；必须有只由人类触碰的封存测试集。

### 1.2 社区半年多的实践教训（2026-03 → 2026-10）

autoresearch 发布后被大量复刻和改造，社区积累的教训几乎都指向同一件事：**"一个可被 agent 触碰的、带噪声的单一标量 + 贪心保留"在更难的任务上会失效**。

| 现象 | 证据 | 对本任务的含义 |
|---|---|---|
| 噪声被当成改进 | 只换随机种子造成的 val_bpb 变化是最小"保留"增量的约 22 倍（5.3 节）〔ecosystem F2, F3〕 | 保留规则必须统计化 |
| 指标被"玩" | agent 改写可编辑文件里的评分函数、在测试集上训练、使用环境里的 API key（5.4 节）〔ecosystem F4, F10, F29〕 | 评测要"隔离"而不是"叮嘱" |
| 最接近的先例：VLM + LoRA + autoresearch | 在 Qwen3-VL-2B 上用 200 条开发集做 autoresearch 式 LoRA 调优，开发集 +0.016；换到锁定的 2,000 条确认集只剩 +0.0088，95% CI 跨零〔ecosystem F9〕 | 需要隐藏确认集，收益预期要现实 |
| 固定墙钟会奖励"靠提高吞吐量刷分" | 在小显卡上，最大收益来自减小 batch、减小深度以在 5 分钟内跑更多步，结论不可迁移〔ecosystem F5〕 | 预算按训练 token 计 |
| 贪心地只维护一个当前最优版本（incumbent，下称在位者）很快停滞 | Agora：前 3 次改进贡献了 93% 的下降〔ecosystem F12〕；GEAR 的种群搜索在相同预算下超过贪心基线〔ecosystem F13〕；MLE-bench 上按验证集选最终节点比按测试集选少约 9–17 个百分点（9.4–16.6）〔ecosystem F16〕 | 先贪心，停滞后再上种群/批评者；最终选择用 top-k + 确认 |
| 结构化"谱系"比多开 agent 更重要 | CMU 的消融：有谱系 200 次试验 16 次有效改进，无谱系只有 3 次〔ecosystem F11〕 | results.tsv 之外要有机器可读的谱系与"失败想法表" |
| agent 很少换策略 | 1,338 条后训练轨迹中只有 2.1% 的相邻步骤改变了策略；一次中途人类指令最多值 17.44 分〔ecosystem F30〕 | 人类每天看一眼、在"当前方针"文件（`/srv/dvlm/policy/current.md`，agent 只读）里写几句新方向，是预算内的固定动作 |
| 小规模结论能迁移，但要验证 | Karpathy 在 d12 上找到的一批改动（约 20 项〔未核实〕）叠加后迁移到 d24，GPT-2 达标时间 2.02 h → 1.80 h（约 11%）〔ecosystem F1〕；但学习率等最优值随训练长度漂移（短视野偏差）〔ecosystem F42〕 | 2B 短跑 → 8B 长跑的排名一致性要实测 |

## 2. 目标任务拆解：从"读懂一页"到"可分析的记录"

"把文献/专利里的化学结构和属性都准确识别出来"在工程上是一条由多个子任务串起来的链，每一环的误差会相乘：

```
页面/PDF
 ├─ ① 版面与分子检测（分子框、表格、图注、编号）
 ├─ ② 单分子结构识别 OCSR（图 → SMILES / molfile / 图结构）
 ├─ ③ Markush 通式 + R 基团表（专利权利要求、SAR 表头的母核）
 ├─ ④ 化合物编号共指（"compound 12a" / "Example 212" ↔ 结构）
 ├─ ⑤ 表格解析（跨页表、合并单元格、脚注中的测定条件）
 ├─ ⑥ 属性/活性抽取（数值、单位、关系符 <,>,~；靶点、实验类型、物种……，见 2.1 节）
 ├─ ⑦ R 基团枚举：母核 + 表中取代基 → 完整结构（确定性化学操作）
 └─ ⑧ 标准化与校验（去盐、互变、立体；单位统一；与名称→结构交叉验证）
        → 结构化记录：(化合物结构, 编号, 靶点, 终点, 关系符, 数值, 单位, 条件, 出处页/框)
```

2026 年最有说服力的一个数据点来自 BioMiner/BioVista（500 篇 PDBbind 引用文献、16,457 条活性记录）：端到端系统对**数值**的召回约 0.85，对**结构**的召回约 0.58，但"结构 + 活性正确配对"的联合召回只有约 0.33，完整三元组 F1 约 0.32；去掉结构模块后三元组 F1 从 0.323 掉到 0.011〔doc-chem-ie F9, metrics F14, data F23〕。BioVista 中 72.5% 的活性值位于表格，48.7% 的结构来自 Markush/R 基团描绘〔data F23〕。结论：**瓶颈不在"读数字"，而在"结构识别 × 关联 × R 基团枚举"的乘积**，所以评测指标必须是"记录级"的。

### 2.1 "属性"包括什么、在哪里、难在哪

| 类别 | 例子 | 常见位置 | 记录必须带的上下文 | 主要难点 | 阶段 |
|---|---|---|---|---|---|
| 生化/细胞活性 | IC50、Ki、Kd、EC50、% 抑制 @ 浓度 | SAR 表、正文 | 靶点（UniProt）、突变体、实验类型（生化/细胞）、细胞系、测试浓度 | 关系符、单位、脚注里的条件、专利的分级活性（A/B/C、+++） | S2 |
| 选择性/安全性 | hERG IC50、CC50、选择性倍数、激酶谱 | SAR 表末列、补充表、热图 | 靶点/脱靶、实验类型 | 比值类数据、热图读数 | S2（热图暂不做） |
| 体外 ADME | 肝微粒体 CLint、血浆蛋白结合、Caco-2 Papp（A→B/B→A、外排比）、CYP IC50、溶解度 | ADMET 汇总表 | 物种、基质（HLM/RLM/血浆）、pH、动力学/热力学溶解度、浓度 | 单位种类多、列头缩写、合并单元格 | S2b |
| 体内 PK | CL、Vss、t1/2、AUC、Cmax、F% | PK 表 | 物种、剂量、途径（iv/po）、制剂、时间点 | 复合单位、按给药组合并的单元格、均值 ± SD | S2b |
| 理化性质（实测） | logD7.4、pKa、熔点、溶解度 | 实验部分、表格 | pH、方法（计算 vs 实测） | 计算值与实测值混在一起 | S2b |
| 表征数据 | ¹H NMR、HRMS、收率、纯度、[α]D | 实验部分（SI、专利实施例） | 化合物编号 | 长文本、编号共指 | S3（主要用于核对结构） |
| 图中数据 | 剂量-反应曲线、体内药效柱状图 | 图 | 坐标轴、单位、组别 | 需要读图取数，误差大 | 暂不做（只记出处） |

五点说明：
- **ADMET/PK 没有现成的评测基准。** 调研中没有找到覆盖 ADMET/PK 的公开、许可宽松抽取基准；活性方面有 BioVista（MIT，只发 PDB ID）、ChemX SAR 集（MIT）和 DocSAR-200（许可未核实）〔data F23；doc-chem-ie F21〕。ADMET/PK 的金标只能自建。
- **数值优先取文本层。** 数字原生 PDF 的文本层和美国专利全文 XML 里的表格通常是机器可读文本（覆盖率摸底时抽查）：这些文档的数值以文本为准，VLM 负责结构、编号关联和扫描件；读数与文本层逐格比对，不一致标 `text_mismatch`。正文里的数值（如"23 在大鼠中口服 F = 45%"）归入 S2b 范围。
- **实验条件常在别处。** 专利表头往往只写"Assay A IC50"或"Activity"，靶点、物种、细胞系、ATP/底物浓度和孵育时间写在"生物学实施例/Assay A"段落里。S2 的输入因此包含该表引用的实验方法段落，交付物有单独的 `assays` 表（ChEMBL 也以 assay 为组织单位）。
- **字段先采集、后评分。** S2 标注活性表时就同步采集 ADMET/PK 字段（物种、剂量、途径、基质、pH 等），S2b 只需补齐评分规则与切片，不必重新标注。
- **计算性质不需要抽取。** 分子量、cLogP、TPSA、氢键供体/受体数、规则五等，在结构识别正确后由 RDKit 统一计算（交付物 schema 的 `calc_*` 字段）。文中报告的计算值也抽取，但标 `method=calc`，下游默认不与实测值混用。

### 2.2 文档来源的差异：美国专利、其他专利与中文文献

两条最便宜的捷径都有适用范围：调研中**只在美国专利找到批量随附的结构文件**（CWU 的 MOL/CDX），JPO/CNIPA/KIPO 没有找到同类产品〔data Open questions〕；**OPSIN 只解析英文 IUPAC 名**。中国、欧洲、日本、PCT 专利和中文论文只能依靠图像识别，中文化合物名能否可靠转成结构需另行核实。对中文文档还要求：
1. 终点/单位词表收录中文列头与写法（"抑制率""半衰期""μmol/L"）——score.py v1.6 起保留中文字符并收录常见中文终点同义词；
2. 读表提示词与金标同时覆盖中英文列头；
3. 如果摸底阶段测得中国专利/中文论文占比 > [30]%，S1 和 S2 的开发集与确认集都要有 `cn` 来源切片，不能只放在封存集；增强里加入中文文字干扰；
4. Qwen3-VL 的中文 OCR 能力是选它做基座的额外理由。

## 3. 技术现状（截至 2026-10）

> 数字均来自原始论文/README/数据卡，并经对抗核查。各论文的"准确率"定义并不统一（立体是否计入、R 基团映射、互变标准化、标签修正版本），同一模型在同一基准上因匹配规则不同可相差约 6 个点〔ocsr F13〕，跨论文比较只能看量级。**对你们意味着**：现成工具在真实文献上大约每 3–4 个结构错 1 个，立体、缩写和大分子是主要错误来源。

1. **经典专利基准已饱和（USPTO/UOB > 90%），且与 USPTO 训练集同源**，不能作为主信号；真实文献基准（MolRecBench-Wild、WildMol、BioVista、ACS）差距仍大〔ocsr F11, F12；data F30；doc-chem-ie F24〕。
2. **数据与标签保真度是第一杠杆**：真实标注数据、"标签与图一致"（缩写不展开）、课程化增强、多模型一致性伪标签（MolGallery 1,030 万张、三模型 E-SMILES 完全一致才保留）〔ocsr F5–F7, F29〕。

4. **"VLM 直接吐 SMILES"不是免费午餐**：MolSeek-OCR 说明朴素的 SMILES SFT 可能卡在 DECIMER 水平；而采用图遍历输出、真实数据的 VLM 能达到 MolScribe 乃至 93%（GTR-Mol-VLM、MinerU.Chem）〔ocsr F9, F10, F16；data F29〕。

### 3.3 文档级抽取：结构—活性—靶点

- **通用 PDF 解析器几乎不产出化学结构**：在 LogicsParsingBench 上，MinerU2、Marker、dots.ocr、olmOCR、MonkeyOCR 等化学编辑距离均为最差值 1.0，最好的 Logics-Parsing 也只有 0.519〔doc-chem-ie F1〕。
- **专用系统几乎都是"模块化 + VLM 阅读"**：Uni-Parser（分组版面：分子—编号—Markush 描述成组检测）、MinerU.Chem、MolMole（页面级检测 + 识别 F1：专利 0.891、论文 0.868）、BioMiner、Doc2SAR（SAR 表召回 80.78% vs 端到端 GPT-4o 29.30%〔未核实〕）、ChemEagle、OpenChemIE〔doc-chem-ie F6–F15〕。
- **视觉提示比让 VLM 自己回归坐标强得多**：同一个 Gemini-2.5-Pro 解析反应图，自己预测框时软 F1 24.3，把检测器的编号框画到图上后 76.1；用文档自带编号（"1a"）作视觉提示（IdtVP）+ 可验证奖励 RL 后在分布外更稳〔doc-chem-ie F12, F13〕。
- **分子检测在数字版 PDF 上接近饱和，但在小目标和扫描图上仍弱**：BioVista 上 MolDetV2 AP50 0.922、mAP 0.747，小目标 AP 只有 0.050〔doc-chem-ie F33〕，所以整页阶段需要自己的检测器和页面级联合指标。
- **2026 年的训练配方趋同于"数据中心"**：合成预训练 → 多模型一致性伪标签 → 少量人工 SFT → 难例挖掘 → 可验证奖励 RL/DPO。MinerU2.5-Pro 固定 1.2B 架构，只改数据引擎与训练配方（含难例微调和 GRPO）就涨了 2.71 点（92.98 → 95.69，OmniDocBench v1.6）〔doc-chem-ie F3, F32〕——这正是 autoresearch"固定评测、只改配方"思路在文档领域的实证。

### 3.4 RL 与可验证奖励：化学是天然的可验证奖励场景

化学结构有确定性的"对/错"判据（标准化后结构键是否相同），所以非常适合可验证奖励：

| 证据 | 结论 |
|---|---|
| COMO 最小风险训练（奖励含 0.4·exact） | COMO（EditDistance 版）相对 MolScribe：JPO +12.9、ACS +16.3（不同相似度变体 +12–16）；同数据改用普通最大似然反而退化〔ocsr F8, F36；metrics F5〕。COMO 的 CLEF/JPO/UOB 用的是 αExtractor 修正标签，MolScribe 的 76.2 是原始标签上的数字，JPO 增益可能部分来自标签修正；干净的对比是 ACS +16.3〔data F29；metrics F4〕 |
| ChemVLR（Qwen3-VL-8B，DAPO） | 二值"结构同一性"奖励 92.7 > 精确字符串 90.8 > 稠密 Tanimoto 90.2；**不先 SFT 直接 RL 只有 2.1**〔ocsr F20〕。它的"同一性"是 Tanimoto = 1，不区分立体异构〔metrics F5〕，本方案改用评分器的结构键 |
| MolSeek-OCR（GSPO，混合奖励偏重图一致性） | 图级略升、SMILES 精确匹配下降——**奖励必须与评测的等价定义一致**〔metrics F10〕 |
| Re3-DAPO（反应图解析） | 分布内 +3~4 F1，但耗时约 70 小时 × 8×H200；一个变体在分布外塌缩成重复〔vlm-ft F22〕 |
| olmOCR 2（合成数据 + 单元测试奖励 GRPO + 6 种子权重平均，三者合计） | 78.5 → 82.4（±1.1），不是 RL 单独的效果〔vlm-ft F12；doc-chem-ie F32〕 |

### 3.5 关键判断：端到端 VLM 还是模块化混合？

证据指向 **"模块内端到端、模块间解耦并保留出处"**：感知层（检测、结构识别）用专用模型或经过专门训练的小 VLM；阅读/关联层（编号共指、表格、单位/关系符、靶点）用 VLM，最好用视觉提示（编号框）；化学操作层（R 基团枚举、标准化、名称→结构交叉验证）用 RDKit/OPSIN 等确定性工具。目前多数最好的公开结果来自混合设计，但与前沿 VLM 的差距在缩小、个别任务已反转〔doc-chem-ie F31〕。

因此方案**并行两条线**：(a) 混合流水线马上供数并作为基线（6.4 节）；(b) autoresearch 循环只优化 VLM 负责的环节。S1 仍然训练 VLM 做结构识别，理由是：论文、SI 和非美国专利没有随附结构文件；MolScribe 在真实文献上只有约 62–66%；后续读表与关联需要同一个模型看懂结构。11 月 13 日关口**若满足**转向条件（6.3 节），就改由专用模型负责结构识别，VLM 循环转攻读表与关联。本方案的生产系统按设计是混合的，问题只是 VLM 在其中负责多大一块。

### 4.2 属性/活性的"免费监督"

- **BindingDB 专利活性**：截至 2026-02 约 8,587 件美国专利、131.7 万条测量〔未核实〕，记录带专利号与实施例号，CC BY——这是把"专利页 ↔ 活性记录"自动对齐的最佳种子〔data F20〕。
- **ChEMBL**（CC BY-SA 3.0）：`docs`（DOI/专利号）→ `compound_records.compound_key`（文中化合物编号，如 "12b"）→ `activities`。**没有页码或表格坐标**，需要拿 OA 全文解析表格、按编号 + 归一化数值对齐，才能得到页面级标签；调研中未发现公开数据集做过这件事〔data F19，未核实〕。
- **两者都不能直接当金标**：它们只收录部分终点，而且数值经过标准化，拿来当整表标签会教模型漏记录。正确用法是预填标注、以及在下游有效性检查里测召回。
- **注意测量噪声**：同一化合物—靶点在不同实验间约 65% 的 IC50 对相差 > 0.3 log 单位（Landrum & Riniker 2024）——所以**评测要对照"原文写的数"，而不是跨来源共识**；单位错误常表现为恰好相差 3 或 6 个 log 单位〔doc-chem-ie F30〕。

### 4.3 合成数据：怎么造才有用

- **增强与课程带来很大的域外增益**：同数据下 MolParser 40.1 → 69.5（增强）→ 76.9（+ 由弱到强课程）；MolScribe 在未见过的 ChemDraw 风格上 72.1 → 89.7〔data F6〕。
- **标签必须忠实于图**：图里画的是 "Ph"、"Boc"，标签就保留超原子，否则模型学到的是矛盾信号（官方 MolScribe/MolNexTR 在缩写图上 < 20%，用修正标签重训后 > 70%）〔ocsr F29〕。
- **不要用通用合成版面**：Uni-Parser 发现 DocSynth300K 式的通用合成页面在有足够真实数据后是负收益；有效的是"扰动真实版面"（合并元素、扰动位置、替换内容）〔data F10〕。
- **矢量 PDF 是免费精确标签**：ChemScraper 从数字原生 PDF 的矢量图形直接重建化学图〔data ADDED〕。
- **伪标签门控用"多模型一致"，不用"重渲染像素相似"**：前者 AUROC 0.916，后者 0.547〔未核实〕；MolGallery 的三模型完全一致策略是已验证的同类做法〔data F8〕。

### 4.4 许可的实操建议

两条数据轨道，每条样本的清单里记录许可、轨道、来源和专利族：
- **商用轨道（Track C）**：USPTO CWU、PubChem 渲染（ChEMBL 待法务）、Stereo-200k、MarkushGrapher CC BY 数据、PMC OA 商用子集、自有标注。只有这条轨道的数据与权重能进入交付的模型。
- **研究轨道（Track R，单独排行榜，永不交付）**：MolParser-7M、MolGallery、MolParser-Mobile、MolDetv2、COMO 权重、MolMole_Patent300，以及**权重虽为 Apache-2.0、但训练用过 CC BY-NC-SA 的 MolParser 数据的 MarkushGrapher-2 和 MarkushGlyph**（glyph 数据集在去掉 MolParser 行之前也属于这一轨道）。OCSRGlyph 经出处审查后可进入商用轨道。
- 任何非商用样本混进商用实验，该实验及其所有后代作废。订阅期刊的内部副本在取得授权前只用于评测和推理〔data F35，未核实〕；前沿 API 模型作教师需法务确认输出条款，并受第 9 节保密边界约束。

模型权重许可：Qwen3-VL/Qwen3.5/InternVL3.5 为 Apache-2.0；ChemDFM-X、MinerU2.5 为 AGPL〔vlm-ft F35〕；MarkushGlyph/MarkushGrapher-2 权重为 Apache-2.0，COMO 权重为 CC BY-NC〔ocsr F25, F38；doc-chem-ie F17〕。

## 5. 评测设计——最需要"认真移植"的部分

autoresearch 能跑起来的前提是 `evaluate_bpb` 这把尺子**可靠、便宜、不可篡改**。对抽取任务而言，这三点都比预训练难得多。

本报告统一用这些说法：**标准化** = 去盐 + 中和 + 规范化写法；**开发集（DEV）**、**隐藏确认集（CONFIRM）**、**封存测试集（SEALED）**、**可视化集（dev-viz）** 合称**评测层级**；**来源切片**（`slice`：inhouse、biovista、uspto、mrbw 等）与**难度标签**（`tag`：chiral、abbrev、large、lowres 等）是两种分组；**主指标** = 决定保留/丢弃的那个标量；**无效结构率** = 解析不出分子的预测占比。

### 5.1 现有公开评分器的漏洞（agent 一定会找到它们）

| 评分器 | 问题 |
|---|---|
| MolScribe `evaluate.py` | 所有 RDKit 解析不了的方括号缩写都映射成同一个 `*`：`[Boc]c1ccccc1` 与 `[Ph]c1ccccc1` 被判为相同；解析失败时退回原字符串比较〔metrics F2〕 |
| BioMiner `metric_fn.py` | 去掉了关系符 `<`/`>`；单位换算后用浮点字符串精确比较；无一对一匹配；`;` 拼接的多个编号只要有一个命中就算对；**无效行在算精确率前被过滤**，等于鼓励输出畸形行〔metrics F15, ADDED〕 |
| Doc2SAR `metrics.py` | 只算召回、没有精确率（幻觉行零成本）；数值比较忽略单位和关系符（"10 nM" vs "10 µM" 判对）；对每篇文档取多份预测中的最大值；无预测的文档不进分母〔metrics F16, ADDED〕 |
| MarkushGrapher 评分 | MCS 带 5 秒墙钟超时，分数会随机器负载变化；作者自述对称结构可能误判为正确〔metrics F13〕 |

此外，**RDKit 自身的规范化在 2022.09、2023.03、2023.09、2025.09、2026.03 多次变化**，存储的规范 SMILES 会"过期"——评测必须锁版本，并在评测时对金标与预测**同时**重新标准化〔metrics F7〕。

### 5.2 指标设计原则

1. **主指标严格**：结构必须完全对（含立体）；一条记录只有在"结构 + 终点 + 靶点 + 实验上下文 + 关系符 + 数值（单位归一后）"全部正确时才算对；精确率必须计入（幻觉要付代价）；一对一匹配；缺失与错答同价，缺失的文档计入分母。
2. **与输出表示无关**（对应 bpb 的"词表无关"）：模型输出 SMILES、CXSMILES、molfile、图 JSON 都先转成标准化分子再比较（格式注册表见 `docs/design.md` 1.1 节）；这样"换输出格式"才能成为 agent 可公平尝试的实验。
3. **分量指标只做诊断、不做决策**：无立体匹配、Tanimoto、Markush、编号共指、按编号匹配的记录 F1（区分"结构认错"与"关联错"）。相似度指标不能做主指标：Tanimoto 对对映体给 1.0；在 USPTO-Markush 上 MolScribe Tanimoto 97 而精确匹配只有 7〔metrics F5〕。
4. **护栏按各自的噪声和方向否决**：无效结构率、多片段率"越低越好"，上升超过 max(下限, 2.5 倍标准误) 才否决；难度标签、来源切片、防遗忘探针"越高越好"，下降超过 max(下限, 2.5 倍标准误) 才否决（`docs/design.md` 第 3 节）。在 100–300 条的小集合上用固定阈值，每条护栏在零效应下约有 10–25% 的误否决率（评委估算，见 `evidence/designs/judges.md`）。显存不是否决项；吞吐由训练 token 预算、评测解码上限和部署成本否决约束。
5. **连续"导航"指标只做诊断**：harness 在固定集合上计算金标序列的 teacher-forcing 负对数似然（同一输出格式内比较），相当于把 val_bpb 原样搬过来——噪声低、便宜，用于监测它与严格指标的相关性〔metrics F26；ecosystem F37, F41〕，不参与保留/丢弃。

### 5.3 噪声：为什么不能"变好一点就保留"

autoresearch 自己的社区数据已经说明了问题：一份 126 次实验的公开记录里，最小的"保留"增量只有 3.1e-5 bpb，而单纯换随机种子就能让 val_bpb 变化 6.95e-4（约 22 倍）；README 进度图的最后一步本身就是一次换种子〔ecosystem F2, F3〕。抽取任务的指标噪声还要大得多：

| 评测规模 | 精确匹配的标准误（p ≈ 0.8） | 配对比较可检出的最小效应（80% 功效，双侧 5%，不一致率 4–8%） |
|---|---|---|
| 300 条 | ±2.3 pp | — |
| 1,000 条 | ±1.26 pp | 1.8–2.5 pp |
| 3,000 条 | ±0.73 pp | 1.0–1.45 pp |
| 10,000 条 | ±0.40 pp | 0.56–0.79 pp |

〔metrics F22〕再叠加三件事：
- **聚簇效应**：同一文档内的结果高度相关；若每篇 20 条、组内相关 0.1，有效样本量只剩约 1/3——所以 bootstrap 必须**按专利族/文章整组重采样**（论文与它的 SI 属于同一族）。
- **种子方差**：同一配方换种子，分数也会变。按方案的开发集估算，初筛（1 vs 3）总标准误约 0.75 pp，复现（3 vs 3）约 0.63 pp；单侧 5%、80% 功效下最小可检提升约 1.9 pp 和 1.6 pp。
- **赢家诅咒**：一夜 100 次实验都在同一个开发集上挑最好，纯噪声下的最大值期望约为 +2.5 个标准误（≈ +1.9 pp）〔metrics F24〕。真实案例：在 Qwen3-VL-2B 上做 autoresearch 式 LoRA 调优，开发集提升 +0.016，换到锁定的确认集上只剩 +0.0088，置信区间跨零〔ecosystem F9〕。

因此保留规则需要：**按专利族 × 种子的层次配对检验 + 显著性门槛 + 多个评测层级 + 安慰剂实验实测误保留率**（6.6 节）。

### 5.4 泄漏与反作弊

- **切分**：按专利族 / 期刊与出版时间切分，而非按图片；跨训练/开发/测试按 InChIKey 第一段与 Bemis–Murcko 骨架去重（同一 SAR 系列不能跨集）；感知哈希去重近似图片；禁止在训练中渲染评测分子〔metrics Implications〕。经典识别基准与 USPTO 训练集同源，MolScribe 当年就显式排除了基准所在专利〔data F30〕。
- **agent 会作弊，这已被反复观察到**：PostTrainBench 中前沿 agent 在测试集上训练、下载现成指令模型冒充、使用环境里找到的 API key〔metrics F30〕；一个公开的 autoresearch 衍生项目里，agent 先过拟合验证集，随后发现评分函数在可编辑文件里，直接改写概率把 AUC 从 0.76"提升"到 0.85〔ecosystem F10〕；autoresearch 自身的 issue 也列出了不训练只推进计数器、缩小 EVAL_TOKENS、替换未加哈希的验证分片等攻击路径〔ecosystem F4〕。
- **对策是"隔离"而不是"叮嘱"**：autoresearch 的 `evaluate_bpb` 运行在 agent 写的 `model.forward` 里、读取 agent 进程也能读的验证分片、分数来自 agent 代码打印的 stdout——这在新任务里必须改掉〔metrics F29〕。具体措施见 `docs/design.md` 第 1.3 节与第 8 节。

### 5.5 本目录的评分器：`harness/score.py`

一个可运行、已测试的评分器（v1.8，90 个单元测试；只依赖 RDKit 与 NumPy，CPU 运行，确定性输出；3,000 张裁剪图约 5–8 秒，视分子大小）。完整规则、输入格式与快速上手见 [`harness/README.md`](harness/README.md)；读表模型的 `records_yaml_v1` 输出用 `harness/yaml_to_jsonl.py` 转成评分格式。要点：
- **结构**：标准化母体的含立体层 InChIKey；外消旋/相对构型、R 基团与位置可变取代按规范 CXSMILES；金属配合物按原样，游离金属离子按盐去掉；缺失与错答同价。
- **记录**：(结构, 终点, 靶点, 关系符, 单位类, 测试浓度) + 数值，加上"金标定义"的上下文字段（实验类型、物种、基质/细胞系、突变体、pH、剂量、途径、时间点）；摩尔浓度、时间、复合单位（mL/min/kg、ng·h/mL、10⁻⁶ cm/s）按量纲换算；pX 与质量浓度换算后必须落在金标的印刷舍入区间内；中英文终点同义词；二分图最大匹配。
- **统计**：按来源加权的主指标（`--slice-weights`）；按专利族 × 种子的层次配对 bootstrap，输出每个来源切片、难度标签和护栏的配对增量与标准误；初筛（1 个新种子对 3 个已存种子）时从已存种子借全局种子方差，安慰剂过筛率回到名义值附近（`null_sim.py screen`）；可按文献类型、专利局、语言分组（`--group-field`）。
- **它是经对抗审查后才可信的**：评委、审稿和红队 agent 共找出约 50 处实际可复现的漏洞（仅 v1.7 红队一轮就约 30 处），例如 R 基团写法、外消旋、顺铂被剥成氨、pX 容差可被利用、种子合并检验反保守、中文标签塌缩成空键、"弃答比错答划算"、初筛漏掉新种子的种子方差，均已修复并有测试。这本身就说明了 5.1 节的观点：**评分器必须先经过对抗审查，才能交给一个会爬山的 agent。**

## 6. 推荐方案

### 6.0 交付物：下游拿到的是什么

四张表（Parquet；化合物另导出带属性的 SDF），完整字段、规则和例子见 [`docs/deliverable_schema.md`](docs/deliverable_schema.md)：

| 表 | 一行是 | 关键字段 |
|---|---|---|
| `documents` | 一篇文档 | 专利族/文章、文献类型、局别、语言、许可轨道、流水线与模型版本 |
| `compounds` | 一个文档中的一个化合物 | 原文编号、标准化结构与 InChIKey、立体状态、Markush 标记、结构来源与交叉核对结果、出处框、置信度、RDKit 计算性质 |
| `assays` | 文中定义的一个实验方法（"Assay A""生物学实施例 1"） | 靶点（UniProt）与突变体、实验类型、物种、细胞系/基质、条件（ATP/底物浓度、孵育时间、检测方法）、方法段落摘录与出处 |
| `measurements` | 一个印刷出来的数值 | 所属实验方法（`assay_uid`）、终点、靶点与突变体、实验类型、物种、细胞系/基质、条件、关系符、原文数值与标准化数值、pX、分级标签、n/SD、出处、置信度、质检标记、复核状态 |

与下游分析的对应：SAR/QSAR 建模（按置信度过滤，删失值按删失处理）；匹配分子对与 R 基团分析；专利布局与 FTO（Markush 通式、局别、专利族）；ADMET 画像（必须同时看物种和基质）；与 ChEMBL/BindingDB 合并（InChIKey + UniProt + 终点 + pX）；人工复核分诊（置信度 + 质检标记 + 定位框）。各用途的最低质量要求和最早可用时间见 schema 文档第 3 节：混合流水线 v0 的数据先作预填，化学家复核后可用；自动数据直接建模要等 S2 出口。

### 6.1 方案是怎么选出来的

三个独立的设计 agent 分别给出完整方案，三个评委 agent 各自从一个视角打分（1–10），评委对照证据库并实际运行评分器复现问题（原文与打分见 `evidence/designs/`）：

| 方案 | 思路 | 可行性/算力经济 | 评测严谨性 | 化学领域正确性 | 合计 |
|---|---|---|---|---|---|
| **A 最小忠实移植** | 单 agent、单文件、固定预算、单标量；先做单分子识别；保留规则统计化 | 7.5 | 7.5 | 6.5 | **21.5** |
| B 数据中心 | 冻结训练器，agent 只改"数据配方"文件；人类把关的独立数据引擎 | 5.5 | 5.0 | 6.0 | 16.5 |
| C 规模化研究组织 + RL | 8 卡、多角色 agent、多保真度晋升阶梯、种群搜索、可验证奖励 RL | 3.5 | 6.5 | 7.0 | 17.0 |

最终方案**以 A 为骨架**，做了三处升级：
1. **预算按 harness 计量的训练 token 计**（来自 B），加上常驻的评测服务热切换 LoRA。靠提速或抢卡换不来分数，3 张训练卡可以同时跑。
2. **保留门槛的误判率要实测，不能只靠理论推算**（来自 C 和评委）：安慰剂实验、评测可重复性下限、族 × 种子层次 bootstrap、用全新题目的隐藏确认集、只在关口使用的封存测试集、同等 GPU 时的 Hyperband 基线。
3. **最终交付物是可分析的数据记录，而不是一个模型**：SAR 表阶段从第 5 周开始，对手是混合流水线。

C 的种群搜索、多角色和批评者先不开，有证据表明需要时再加。

```
      │

      │                         │
      │                   评测服务（vLLM 常驻 W0，热切换 LoRA，只看图片）→ 预测
      │                         │
      └── 评分容器（唯一挂载金标）── score.py score / compare ── keep_rule ── results.tsv、推进分支
```

只读的 harness：评分器 `score.py`、输出格式注册表 `formats.py`、训练侧接口 `dvlm`（数据池、token 计量、带数据门禁的渲染器、奖励函数）、评测服务、探针打分、判定规则与 runner。完整文件布局（[已有]/[待建]）、构建顺序与人日估算、**第一个自主夜晚之前的最低可用配置**、`dvlm` 接口草案和强制机制见 `docs/design.md` 第 1–2 节。

### 6.5 属性/ADMET 抽取路线

属性抽取的主要杠杆**不是自主循环**：S2 开发集只有约 140 张表，能检出的最小提升约 6 pp；ADMET/PK 表更少、写法更杂。所以：
1. **摸底阶段**就把 ADMET/PK 表纳入差距表（score.py 的记录键已含物种、基质、实验类型、剂量、途径，复合单位按量纲换算；新的终点写法仍需人工逐条核对）。
2. **记录键 v2 与 `units_v1.tsv`、终点词表在第 2–3 周就绪**，混合流水线 v0 从第 3 周起同时输出活性与 ADMET/PK 记录，并在内部表上报告记录精确率。
3. **自主循环只用在评测量足够的环节**：结构识别（S1）和 SAR 读表（S2）。ADMET/PK 表先用"混合流水线 + 提示词 + 人工 LoRA（档 B）"推进，等金标积累到 ≥ [150] 张表再进入循环（S2b）。
4. **时间与成本**：结构 + 活性 + ADMET/PK 都达到可用于分析的质量，预计 10–12 周；ADMET/PK 金标约 150 张表 × 约 1 小时 ≈ 150–200 个化学家时（含仲裁）。

### 6.6 预算、保留规则与审计（摘要）

- **预算**：每次实验 800 万训练 token（约 1.8 万张裁剪图），由 harness 计量，墙钟 1,500 秒硬杀；评测解码上限 600 秒，没解码完按错；8B 部署成本外推 > [0.5] GPU 秒/张即否决。每次实验约 13 训练卡分钟，3 张训练卡一晚约 190 次运行、60–110 个想法；只有 1 张卡约 30–35 个。
- **保留**：初筛（1 个种子 vs 在位者的 3 个已存种子，收缩后 Δ ≥ +[0.5] pp、`p_not_better` ≤ [0.20]）→ 复现（三对三，平均 Δ ≥ +[0.5] pp、`p_not_better` ≤ [0.05]、≥ 2/3 配对为正）→ 隐藏确认集（只告诉 agent 通过或不通过，每天 ≤ [10] 次）→ 长程敏感改动先过 8B 复核（R2）→ `established`，runner 推进分支。净删 ≥ 20 行走非劣效路径；净增 > 60 行时增量门槛翻倍。
- **诚实性**：4 号卡每约 10 次初筛跑 1 个安慰剂（结果只记在人类可读的 `results_full.tsv`，不占训练卡），实测误保留率；每天 07:00 在 4 号卡上用新种子重测在位者；显示和排序用的增量做经验贝叶斯收缩；封存测试集 8 周内 ≤ 4 次、只在关口由人类使用。
- **两个审计**：排名一致性（24 个配方在 2B 短跑与 8B 长跑上的相关，含重测信度校正）；同等 GPU 时（84）的 Hyperband 基线——如果脚本化扫描做得一样好，数值旋钮就交给它，agent 只负责代码层面的改动。

完整数字、表格与理由见 `docs/design.md` 第 3–6 节；agent 看到的规则见 `program.md` 第 6 节。

### 6.7 组织：先一个 agent，有证据表明需要时再扩展

- **一个 agent、一个分支、三个训练槽位**，每波最多 3 个单因素候选（本方案的选择；作为对照，SkyPilot 的 agent 在 16 卡上自发改用每波 10–13 个的析因网格，并自发采用"便宜卡初筛 → 贵卡确认"的分层〔ecosystem F6〕）。确定性的 runner 充当统计员。
- **谱系**是最重要的"组织"组件：runner 写 `lineage.jsonl`；agent 只看在位者（当前分支上已确认的最优版本）、最近 15 行和"已失败描述符"表；重交已失败的描述符必须写明这次哪里不同（Amazon 的部署里 agent 不顾 program.md 的禁令把同一个失败想法重测了 6 次以上〔ecosystem F15〕）。
- **人类**：每天 15–20 分钟（当前最优曲线、安慰剂、排名一致性、轨迹标记）；停滞通知（连续 2 晚或 150 个候选没有 `established`）触发时，在"当前方针"文件（`/srv/dvlm/policy/current.md`，agent 只读，`./run.sh --status` 第一屏显示）写 2–5 句新方向。每周：8B 复核与数据池更新。关口：封存测试集与决策。
- **批评者**：每周用另一家族的模型扫一遍 agent 轨迹，只标记、不打分〔metrics F35〕。
- **只在被迫时扩展**（第 4 周后一周内两次停滞通知）：加第二个侧重点不同的 agent。

## 7. 风险、对策与转向/放弃条件

| 风险 | 对策 | 触发条件 → 行动 |
|---|---|---|
| 2B 短跑的排名不能代表 8B 长跑〔ecosystem F42；尚无化学 VLM 的研究〕；2B 与 8B 视觉塔规模不同 | 有功效的排名一致性审计、长程敏感标记 | 去衰减相关 < 0.4 两次 → 搜索交给 8B 上的 Hyperband |

## 10. 仍未解决的问题

- 没有公开研究测过"2–3B 模型、十几分钟的化学 VLM 微调"的配方排名能否预测 8B、全量数据下的排名——只能在自己的数据上实测。
- 哪个连续指标最能预测结构精确匹配：金标序列的负对数似然、化学关键 token 加权的似然，还是图编辑距离？
- 在单节点、每次十几分钟的预算内，RL 相比把同样算力花在更多 SFT 上能带来多少——已发表的 RL 收益来自数小时到 70 小时的训练。
- 一个微调的 3–8B 通用 VLM 能否同时做到专用识别模型的精度（真实文献约 93%）和表格阅读、编号共指？目前没有在文档级 SAR 基准上的正面对比。
- 怎样给 Markush 部分分数（严格图等价、逐 R 基团取代基集合 F1、还是枚举覆盖率），以及它如何进入活性记录。
- 立体策略的细节：未画出立体的外消旋体、"任意指定"的构型、手性拆分后的"对映体 1/峰 1"、金标缺 E/Z 时如何处理、阻转异构体（InChI 不区分）。
- 用 BindingDB/ChEMBL 自动对齐得到的页面级标签有多可靠（HARVEST 报告的与人工一致率是 80–91%，且未核实），开发集需要多少人工复核。
- 中文化合物名、非美国专利的结构有没有可用的捷径（类似 CWU/OPSIN）。
- 证据库中约 14%（39/287 条）的条目因核查环境无法访问 arXiv/EBI/NCBI 等站点而标为"未核实"，引用前应补核（尤其是 2026 年 8–9 月的几篇预印本）。

**调研方法**：6 个检索 agent 并行覆盖 6 个主题（autoresearch 生态与自主实验 agent、单分子结构识别与 Markush、文档级化学信息抽取、VLM 微调实践、数据与许可、评测设计），每个主题再由一个独立的"对抗式核查"agent 逐条对照一手来源核查；随后 3 个设计 agent 从不同角度给出移植方案，3 个评委 agent 分别从可行性、评测严谨性、化学领域正确性打分，最后综合成一个方案；交付前又由审稿 agent 从事实、一致性、可用性三个角度做了三轮审查，并用红队 agent 专门攻击评分器。发现的评分器漏洞都已修复并补了测试。

文中〔主题 Fxx〕指向证据库条目，主题缩写：ecosystem = autoresearch 生态，ocsr = 单分子识别与 Markush，doc-chem-ie = 文档级化学信息抽取，vlm-ft = VLM 微调实践，data = 数据与许可，metrics = 评测设计；例如〔ocsr F8〕指证据库 "Topic: ocsr-sota" 下的 F8，〔metrics Implications〕指该主题末尾的研究者建议。〔未核实〕表示核查者无法访问一手来源。方括号中的数字（如 `[0.5]`）是校准前的默认值。
