## 0. 结论速览

**一句话回答**：可以。推荐用 Qwen3-VL（2B 做实验、8B 做产品）+ LoRA，组成"检测 → VLM 阅读 → RDKit/OPSIN 确定性处理"的模块化流水线，分步推进：单分子结构 → SAR 活性表 → ADMET/PK 表与整页、Markush。autoresearch 范式的用处，是在一把固定、隔离、带统计检验的"尺子"下，让 agent 通宵自动优化**训练配方**（数据配比、增强、标签、LoRA、奖励）。成败取决于评测集和评分器，而不是模型架构。**第一步不是训练**，而是用自家 30–50 篇文档量出现成工具的差距（第 8 节"第 0 周"）。

1. **移植本质，改造细节。** 原样保留：固定且只读的评测、只有一个可编辑文件、固定预算、一个与输出表示无关的标量、用 git 做"只进不退"的棘轮、`program.md` 作为"研究组织代码"、NEVER STOP 与简洁性准则。必须改造：评测要**隔离**（上游只靠一句"不许改"来保护 `evaluate_bpb`）；"变好就保留"要**统计化**；评测集分**开发集 / 隐藏确认集 / 封存测试集**三层；预算从"5 分钟墙钟"改为"**每次 800 万训练 token**（约 1.8 万张裁剪图、约 13 分钟训练）"，并从一个一次性构建的**热启动检查点 W0** 出发。
2. **先只优化"单分子裁剪图 → 结构"，同时并行搭混合流水线。** 结构是活性记录的关联键，也是端到端损失的主要来源：最好的端到端系统读数值的召回约 0.85，读结构约 0.58，"结构 + 活性"联合召回只有约 0.33。第二阶段做 SAR 表格（72.5% 的活性值在表格里），之后是 ADMET/PK 表、整页与 Markush。与此同时，用现成组件（美国专利自带的结构文件、OPSIN、许可干净的专用识别模型、零样本 8B 读表）搭一条混合流水线，**立即给下游供数**，并作为每个阶段必须超过的基线。
3. **主杠杆是数据，不是架构。** 文献里最大的收益来自：真实数据占比、"所见即所标"的标签（缩写保留为超原子）、由弱到强的增强课程、手性过采样，以及与评测等价定义一致的序列级奖励（最小风险训练；"结构同一性"二值奖励 RL——文献中用的是 Tanimoto = 1，对立体是盲的，本方案改用含立体层的 InChIKey 相同）。直接对 OCR 型 VLM 做 SMILES 的全参 SFT 是已知的反面案例。
4. **基座：Qwen3-VL-2B-Instruct 做内循环，8B 做长程复核与生产**（Apache-2.0；OCRBench 858/896；每 32×32 像素一个视觉 token）。一台 8×H100 上用 3 张卡训练、1 张卡做常驻评测，一晚可检验 60–110 个想法；只有 1 张卡时约 40 个。
5. **评测是成败关键。** 主流公开评分器都有会被爬山 agent 利用的漏洞（缩写全部塌缩成 `*`、单位与关系符被忽略、无效行不计入精确率、只算召回……）。本目录提供一个经对抗审查的参考评分器 `harness/score.py`：与输出表示无关、立体严格、正确处理 Markush/外消旋/金属配合物/单位换算，带按专利族 × 种子分层的配对检验，以及按来源加权、按难度切片的报告。
6. **噪声比上游大一个数量级以上。** 约 3,400 张的开发集上，"1 个新种子 vs 3 个已存种子"的配对比较标准误约 0.75 pp，能可靠检出的最小提升约 1.6 pp；一夜上百次初筛里挑最好的，纯噪声也能"找到"约 1.9 pp。因此只有通过"初筛 → 三种子复现 → 隐藏确认集"的改动才推进分支，并用安慰剂实验实测门槛的误保留率。**预期保留会很少，这是诚实的代价。**
7. **现实预期。** 真实文献单分子识别：最强系统约 93%（MinerU.Chem，仅在线服务），前沿闭源 VLM 65–75%；开源通用 VLM 零样本参差不齐（InternVL3.5 在修订版 MolRecBench-Wild 上 SMILES 39.80，接近 DECIMER，但图级只有 3.05）；小 VLM + LoRA 已在 Markush 上做到最好（MarkushGlyph，2B）。文档级"结构—活性—靶点"三元组 F1 只有约 0.32——**这正是空白和价值所在**。调研时在 awesome-autoresearch 列表里也没有发现针对化学结构识别或专利化学数据抽取的衍生项目。
8. **端到端 VLM 还是模块化？** 证据指向"模块内端到端、模块间解耦并保留出处"，R 基团枚举交给 RDKit。方案把"VLM 能否胜任结构识别"留作可检验的假设，并在 11 月 13 日的 S1 关口设转向条件：8B 模型在封存的真实文献切片上落后最好的商用许可专用模型 > [5] pp、且前沿每周提升 < [1] pp 连续两周，就让专用模型负责结构识别，VLM 循环转攻表格与关联。两条推理期捷径（**美国专利自带 MOL/CDX 结构文件**；**用 OPSIN 把英文 IUPAC 名转成结构**）只覆盖美国专利和英文文献，中国/欧洲/日本专利和中文文献只能靠图像识别。
9. **许可要提前定。** 商用只用 USPTO 专利数据、PubChem/ChEMBL 渲染、CC BY 的 Markush 数据、Stereo-200k（Apache-2.0）与自有标注；MolParser-7M/MolGallery 是非商用；MarkushGrapher-2、MarkushGlyph 的权重虽是 Apache-2.0，但训练用过非商用数据，**放在研究轨道，不进入商用模型**。
10. **投入估算（6 周）**：一台 8×H100（约 8,064 GPU 时 ≈ 2.17 万美元）、agent API ≤ 2,000 美元、约 18 人周工程（ML 负责人、ML 工程师、化学信息学各 1 人）、约 400 个化学家时（两名化学家约 65% 投入）、约 20 小时法务。S2 的记录级金标是最可能拖期的环节。

## 1. autoresearch 范式拆解：哪些是本质，哪些是偶然

| # | 设计要素 | autoresearch 中的实现 | 它解决的问题 | 移植时必须保留的"本质" |
|---|---|---|---|---|
| 1 | 固定、只读的评测 | `prepare.py::evaluate_bpb`，固定验证分片、固定 `EVAL_TOKENS`、固定 `MAX_SEQ_LEN` | agent 不能"改尺子"；所有实验用同一把尺子 | 评测代码 + 评测集 + 推理引擎全部冻结、只读、可校验哈希；agent 只能通过受限的 `infer_config` 改提示词、输出格式、分辨率与解码方式 |
| 2 | 单一可编辑文件 | 只改 `train.py` | 搜索空间可控、diff 可审、回滚便宜 | 一个 `train.py`（数据配方、增强、标签视图、LoRA、优化器、损失、输出格式），其余只读 |
| 3 | 固定预算 | `TIME_BUDGET=300s`，不含编译 | 实验可比；吞吐可预期（约 12 次/小时） | 固定**训练 token 预算**（每次 800 万）+ 墙钟硬上限；推理开销由评测解码上限和部署成本否决约束 |
| 4 | 单一标量指标 | `val_bpb`，与词表无关 | 明确的爬山方向；架构/分词器改动可公平比较 | S1 用 `val_struct`（严格结构 F1，按来源加权），S2 用结构 F1 与记录 F1 的复合分；对输出表示（SMILES/CXSMILES/molfile/图 JSON）不敏感——先标准化到 InChIKey 再比较，相当于 bpb 的"词表无关性" |
| 5 | git 即实验账本 | 先 commit 再跑；变好就推进分支，否则 `git reset` | 永远站在当前最优点上；可追溯 | 保留，但分支只由 runner 推进；`results.tsv` 不入库 |
| 6 | 贪心爬山 | 严格变好才保留 | 简单、无需人工 | **需要改造**：VLM 微调的评测是离散、小样本、带种子噪声的，需"显著性门控"而非"数值更小即保留" |
| 7 | 简洁性准则 | 小收益 + 丑代码 = 拒；同效果 + 删代码 = 收 | 防止代码熵增 | 保留并量化：净删 ≥ 20 行走"非劣效"路径；净增 > 60 行时增量门槛翻倍 |
| 8 | 自治与容错 | NEVER STOP、10 分钟超时、崩溃自修 | 过夜跑约 100 次 | 保留；训练墙钟硬上限 1,500 秒，崩溃最多自修 2 次 |
| 9 | `program.md` = 研究组织代码 | 人只改 Markdown | 人类杠杆点从"写代码"变成"写研究方针" | 保留，并注入领域知识（化学错误分类、想法先验、禁区）；人类每天在"当前方针"里写 2–5 句话 |
| 10 | 不许加依赖 | 只能用 `pyproject.toml` 里的包 | 环境稳定、防作弊 | 预先锁定 VLM 栈（transformers/peft/trl/vllm/rdkit 等） |
| 11 | 进度可视化 | `analysis.ipynb` 画 running best | 人醒来能一眼看懂 | 扩展：主分数 + 分切片曲线、种子散点、安慰剂通过率 |

### 1.1 两个场景的根本差异

1. **从零预训练 vs 微调已有 VLM**：autoresearch 的模型几秒钟就能初始化，5 分钟足够看到差异；VLM 实验每次有约 1–2 分钟的固定开销（载入模型、解码图片、启动推理引擎）〔vlm-ft Implications〕，而从热启动点出发，学习率、增强这类改动需要几千步才能显出差异，5 分钟预算过短。
2. **评测成本**：`val_bpb` 是 teacher-forcing 下的一次前向；结构/属性抽取必须**自回归生成**再解析，评测是主要开销之一，必须固定推理引擎与解码参数。
3. **指标性质**：bpb 连续、低噪声、样本量极大（约 2,000 万 token）；抽取精度是离散的精确匹配，评测集通常只有几千个样本，标准误不可忽略。
4. **主要杠杆**：预训练的主杠杆是架构/优化器；微调抽取任务的主杠杆是**数据**（合成渲染、增强、真实数据配比、输出格式、课程）、分辨率、LoRA 配置与 RL 奖励。
5. **过拟合开发集的风险**：一夜几十上百次实验都在同一个开发集上挑最优，存在"赢家诅咒"；必须有只由人类触碰的封存测试集。

### 1.2 社区半年多的实践教训（2026-03 → 2026-10）

autoresearch 发布后被大量复刻和改造，社区积累的教训几乎都指向同一件事：**"一个可被 agent 触碰的、带噪声的单一标量 + 贪心保留"在更难的任务上会失效**。

| 现象 | 证据 | 对本任务的含义 |
|---|---|---|
| 噪声被当成改进 | 只换随机种子造成的 val_bpb 变化是最小"保留"增量的约 22 倍（详见 5.3 节）〔ecosystem F2, F3〕 | 保留规则必须统计化 |
| 指标被"玩" | agent 改写可编辑文件里的评分函数、在测试集上训练、使用环境里的 API key（详见 5.4 节）〔ecosystem F4, F10, F29〕 | 评测要"隔离"而不是"叮嘱" |
| 最接近的先例：VLM + LoRA + autoresearch | 在 Qwen3-VL-2B 上用 200 条开发集做 autoresearch 式 LoRA 调优，开发集 +0.016；换到锁定的 2,000 条确认集只剩 +0.0088，95% CI 跨零〔ecosystem F9〕 | 需要隐藏确认集，收益预期要现实 |
| 固定墙钟会奖励"吞吐黑客" | 在小显卡上，最大收益来自减小 batch、减小深度以在 5 分钟内跑更多步，结论不可迁移〔ecosystem F5〕 | 预算按训练 token 计 |
| 贪心单一在位者很快停滞 | Agora：前 3 次改进贡献了 93% 的下降〔ecosystem F12〕；GEAR 的种群搜索在相同预算下超过贪心基线〔ecosystem F13〕；MLE-bench 上按验证集选最终节点比按测试集选少 9–16 个百分点〔ecosystem F16〕 | 先贪心，停滞后再上种群/批评者；最终选择用 top-k + 确认 |
| 结构化"谱系"比多开 agent 更重要 | CMU 的消融：有谱系 200 次试验 16 次有效改进，无谱系只有 3 次〔ecosystem F11〕 | results.tsv 之外要有机器可读的谱系与"失败想法表" |
| agent 很少换策略 | 1,338 条后训练轨迹中只有 2.1% 的相邻步骤改变了策略；一次中途人类指令最多值 17.44 分〔ecosystem F30〕 | 人类每天看一眼、改 `program.md`，是预算内的固定动作 |
| 小规模结论能迁移，但要验证 | Karpathy 在 d12 上找到的一批改动（约 20 项〔未核实〕）叠加后迁移到 d24，GPT-2 达标时间 2.02 h → 1.80 h（约 11%）〔ecosystem F1〕；但学习率等最优值随训练长度漂移（短视野偏差）〔ecosystem F42〕 | 2B 短跑 → 8B 长跑的排名一致性要实测 |

调研时在 awesome-autoresearch 列表里看到了文档 VQA（Qwen3-VL）、OCR、SMILES 生成、药物重定位等方向的衍生项目，但**没有发现针对化学结构识别或专利化学数据抽取的**〔ecosystem ADDED〕。

## 2. 目标任务拆解：从"读懂一页"到"可分析的记录"

"把文献/专利里的化学结构和属性都准确识别出来"在工程上是一条由多个子任务串起来的链，每一环的误差会相乘：

```
页面/PDF
 ├─ ① 版面与分子检测（分子框、表格、图注、编号）
 ├─ ② 单分子结构识别 OCSR（图 → SMILES / molfile / 图结构）
 ├─ ③ Markush 通式 + R 基团表（专利权利要求、SAR 表头的母核）
 ├─ ④ 化合物编号共指（"compound 12a" / "Example 212" ↔ 结构）
 ├─ ⑤ 表格解析（跨页表、合并单元格、脚注中的测定条件）
 ├─ ⑥ 属性/活性抽取（数值、单位、关系符 <,>,~；靶点、实验类型、物种……，见 2.1 节）
 ├─ ⑦ R 基团枚举：母核 + 表中取代基 → 完整结构（确定性化学操作）
 └─ ⑧ 标准化与校验（去盐、互变、立体；单位统一；与名称→结构交叉验证）
        → 结构化记录：(化合物结构, 编号, 靶点, 终点, 关系符, 数值, 单位, 条件, 出处页/框)
```

2026 年最有说服力的一个数据点来自 BioMiner/BioVista（500 篇 PDBbind 引用文献、16,457 条活性记录）：端到端系统对**数值**的召回约 0.85，对**结构**的召回约 0.58，但"结构 + 活性正确配对"的联合召回只有约 0.33，完整三元组 F1 约 0.32；去掉结构模块后三元组 F1 从 0.323 掉到 0.011〔doc-chem-ie F9, metrics F14, data F23〕。另外，BioVista 中 72.5% 的活性值位于表格，48.7% 的结构来自 Markush/R 基团描绘〔data F23〕。结论：**瓶颈不在"读数字"，而在"结构识别 × 关联 × R 基团枚举"的乘积**。这直接决定了评测指标必须是"记录级"的，而不是只看结构识别或只看数值。

### 2.1 "属性"包括什么、在哪里、难在哪

| 类别 | 例子 | 常见位置 | 记录必须带的上下文 | 主要难点 | 阶段 |
|---|---|---|---|---|---|
| 生化/细胞活性 | IC50、Ki、Kd、EC50、% 抑制 @ 浓度 | SAR 表、正文 | 靶点（UniProt）、突变体、实验类型（生化/细胞）、细胞系、测试浓度 | 关系符、单位、脚注里的条件、专利的分级活性（A/B/C、+++） | S2 |
| 选择性/安全性 | hERG IC50、CC50、选择性倍数、激酶谱 | SAR 表末列、补充表、热图 | 靶点/脱靶、实验类型 | 比值类数据、热图读数 | S2（热图暂不做） |
| 体外 ADME | 肝微粒体 CLint、血浆蛋白结合、Caco-2 Papp（A→B/B→A、外排比）、CYP IC50、溶解度 | ADMET 汇总表 | 物种、基质（HLM/RLM/血浆）、pH、动力学/热力学溶解度、浓度 | 单位种类多、列头缩写、合并单元格 | S2b |
| 体内 PK | CL、Vss、t1/2、AUC、Cmax、F% | PK 表 | 物种、剂量、途径（iv/po）、制剂、时间点 | 复合单位、按给药组合并的单元格、均值 ± SD | S2b |

| 表征数据 | ¹H NMR、HRMS、收率、纯度、[α]D | 实验部分（SI、专利实施例） | 化合物编号 | 长文本、编号共指 | S3（主要用于核对结构） |
| 图中数据 | 剂量-反应曲线、体内药效柱状图 | 图 | 坐标轴、单位、组别 | 需要读图取数，误差大 | 暂不做（只记出处） |

两点说明：
- **没有现成的评测基准。** 调研中没有找到公开、许可宽松的属性/活性（含 ADMET/PK）抽取基准〔vlm-ft Open questions〕；BioVista、ChemX、DocSAR 主要覆盖活性。ADMET/PK 的金标只能自建，这也是它排在活性之后的原因。
- **字段先采集、后评分。** S2 标注活性表时就同步采集 ADMET/PK 字段（物种、剂量、途径、基质、pH 等，见 6.10 节），S2b 只需补齐评分规则与切片，不必重新标注。

### 2.2 文档来源的差异：美国专利 vs 其他

两条最便宜的捷径都有适用范围：**随附结构文件（CWU 的 MOL/CDX）只有美国专利才有**；**OPSIN 只解析英文 IUPAC 名**。中国、欧洲、日本、PCT 专利和中文论文只能依靠图像识别，中文化合物名能否可靠转成结构需另行核实。如果团队文档里中国专利占比高：开发集必须有"中国专利"切片，增强里要加入中文文字干扰，第 6 节两条捷径的收益也要打折。第 0 周的差距表（第 8 节）会给出这个比例。

### 3.3 文档级抽取：结构—活性—靶点

- **通用 PDF 解析器几乎不产出化学结构**：在 LogicsParsingBench 上，MinerU2、Marker、dots.ocr、olmOCR、MonkeyOCR 等化学编辑距离均为最差值 1.0，最好的 Logics-Parsing 也只有 0.519〔doc-chem-ie F1〕。
- **专用系统几乎都是"模块化 + VLM 阅读"**：Uni-Parser（分组版面：分子—编号—Markush 描述成组检测）、MinerU.Chem、MolMole（页面级检测 + 识别 F1：专利 0.891、论文 0.868）、BioMiner、Doc2SAR（SAR 表召回 80.78% vs 端到端 GPT-4o 29.30%〔未核实〕）、ChemEagle、OpenChemIE〔doc-chem-ie F6–F15〕。
- **视觉提示比让 VLM 自己回归坐标强得多**：同一个 Gemini-2.5-Pro 解析反应图，自己预测框时软 F1 24.3，把检测器的编号框画到图上后 76.1；用文档自带编号（"1a"）作视觉提示 + 可验证奖励 RL 后在分布外更稳〔doc-chem-ie F12, F13〕。
- **分子检测在药物论文上远未饱和**：常规数字版 PDF 基准上 mAP50 很高，但 BioVista 上小目标 AP 只有 0.050（MolDetV2）〔doc-chem-ie F33〕，所以整页阶段需要自己的检测器和页面级联合指标（6.11 节）。
- **2026 年的训练配方趋同于"数据中心"**：合成预训练 → 多模型一致性伪标签 → 少量人工 SFT → 难例挖掘 → 可验证奖励 RL/DPO。MinerU2.5-Pro 固定 1.2B 架构、只改数据工程就涨了 2.71 点〔doc-chem-ie F32〕——这恰好是 autoresearch "固定评测、只改配方"思路在文档领域的实证。

### 3.4 RL 与可验证奖励：化学是天然的可验证奖励场景

化学结构有确定性的"对/错"判据（标准化后 InChIKey 是否相同），所以非常适合可验证奖励：

| 证据 | 结论 |
|---|---|
| COMO 最小风险训练（奖励含 0.4·exact） | COMO（EditDistance 版）相对 MolScribe：JPO +12.9、ACS +16.3（不同相似度变体 +12–16）；同数据改用普通最大似然反而退化〔ocsr F8, F36；metrics F5〕 |
| ChemVLR（Qwen3-VL-8B，DAPO） | 二值"结构同一性"奖励 92.7 > 精确字符串 90.8 > 稠密 Tanimoto 90.2；**不先 SFT 直接 RL 只有 2.1**〔ocsr F20〕。注意它的"同一性"是 Tanimoto = 1，对立体是盲的〔metrics F5〕，本方案改用含立体层的 InChIKey |
| MolSeek-OCR（GSPO，混合奖励偏重图一致性） | 图级略升、SMILES 精确匹配下降——**奖励必须与评测的等价定义一致**〔metrics F10〕 |
| Re3-DAPO（反应图解析） | 分布内 +3~4 F1，但耗时约 70 小时 × 8×H200；一个变体在分布外塌缩成重复〔vlm-ft F22〕 |
| olmOCR 2（合成数据 + 单元测试奖励 GRPO + 6 种子权重平均，三者合计） | 78.5 → 82.4（±1.1），不是 RL 单独的效果〔vlm-ft F12；doc-chem-ie F32〕 |

### 3.5 关键判断：端到端 VLM 还是模块化混合？

证据指向 **"模块内端到端、模块间解耦并保留出处"**：
- 感知层（检测、结构识别）用专用模型或经过专门训练的小 VLM；
- 阅读/关联层（编号共指、表格、单位/关系符、靶点）用 VLM，且最好用视觉提示（编号框）而不是让它回归坐标；
- 化学操作层（R 基团枚举、标准化、名称→结构交叉验证）用 RDKit/OPSIN 等确定性工具。

但这不是定论：前沿闭源 VLM 在真实文献识别上已超过 MolScribe 一代专用模型，MarkushGlyph 证明 2B VLM + LoRA 能在 Markush 上做到最好。因此方案**并行两条线**：
- **(a) 混合流水线**：用现成组件（美国专利 CWU 结构文件、OPSIN、MolScribe/OCSRGlyph 负责结构，Qwen3-VL-8B 零样本加编号视觉提示负责读表，RDKit 负责枚举与单位归一化）尽快给下游提供带置信度的记录，同时作为每个阶段必须超过的基线；
- **(b) autoresearch 循环只优化 VLM 负责的环节。** S1 仍然训练 VLM 做结构识别，理由是：论文、SI 和非美国专利没有随附结构文件；MolScribe 在真实文献上只有约 62–66%；后续读表与关联需要同一个模型看懂结构。11 月 13 日关口达不到转向条件（6.3 节），就改由专用模型负责结构识别。

生产系统无论如何都是混合的〔doc-chem-ie F31〕；问题只是 VLM 在其中负责多大一块。

### 4.2 属性/活性的"免费监督"

- **BindingDB 专利活性**：截至 2026-02 约 8,587 件美国专利、131.7 万条测量〔未核实〕，记录带专利号与实施例号，CC BY——这是把"专利页 ↔ 活性记录"自动对齐的最佳种子〔data F20〕。
- **ChEMBL**（CC BY-SA 3.0）：`docs`（DOI/专利号）→ `compound_records.compound_key`（文中化合物编号，如 "12b"）→ `activities`（standard_type/relation/value/units）。**没有页码或表格坐标**，需要拿 OA 全文解析表格、按编号 + 归一化数值对齐，才能得到页面级标签；调研中未发现公开数据集做过这件事〔data F19，未核实〕。
- **两者都不能直接当金标**：它们只收录部分终点，而且数值经过标准化，拿来当整表标签会教模型漏记录。正确用法是预填标注、以及在下游有效性检查里测召回（6.13 节）。
- **注意测量噪声**：同一化合物—靶点在不同实验间约 65% 的 IC50 对相差 > 0.3 log 单位（Landrum & Riniker 2024）——所以**评测要对照"原文写的数"，而不是跨来源共识**；单位错误常表现为恰好相差 3 或 6 个 log 单位〔doc-chem-ie F30〕。

### 4.3 合成数据：怎么造才有用

- **增强与课程的作用与数据量相当**：同数据下 MolParser 40.1 → 69.5（增强）→ 76.9（+ 由弱到强课程）；MolScribe 在未见过的 ChemDraw 风格上 72.1 → 89.7〔data F6〕。
- **标签必须忠实于图**：图里画的是 "Ph"、"Boc"，标签就保留超原子，否则模型学到的是矛盾信号（官方 MolScribe/MolNexTR 在缩写图上 < 20%，用修正标签重训后 > 70%）〔ocsr F29〕。
- **不要用通用合成版面**：Uni-Parser 发现 DocSynth300K 式的通用合成页面在有足够真实数据后是负收益；有效的是"扰动真实版面"（合并元素、扰动位置、替换内容）〔data F10〕。
- **矢量 PDF 是免费精确标签**：ChemScraper 从数字原生 PDF 的矢量图形直接重建化学图，可为真实版式提供近乎无误的标签〔data ADDED〕。
- **伪标签门控用"多模型一致"，不用"重渲染像素相似"**：前者 AUROC 0.916，后者 0.547〔未核实〕；MolGallery 的三模型完全一致策略是已验证的同类做法〔data F8〕。

### 4.4 许可的实操建议

建立两条数据轨道，并在每条样本的清单里记录许可、轨道、来源和专利族：

- **商用轨道（Track C）**：USPTO CWU、PubChem/ChEMBL 渲染、Stereo-200k、MarkushGrapher CC BY 数据、PMC OA 商用子集、自有标注。只有这条轨道的数据与权重能进入交付的模型。
- **研究轨道（Track R，单独排行榜，永不交付）**：MolParser-7M、MolGallery、MolParser-Mobile、MolDetv2、COMO 权重、MolMole_Patent300，以及**权重虽为 Apache-2.0、但训练用过 CC BY-NC-SA 的 MolParser 数据的 MarkushGrapher-2 和 MarkushGlyph**（glyph 数据集在去掉 MolParser 行之前也属于这一轨道）。OCSRGlyph 经出处审查后可进入商用轨道。
- 任何非商用样本混进商用实验，该实验及其所有后代作废。订阅期刊的内部副本在取得授权前只用于评测和推理〔data F35，未核实〕；前沿 API 模型作教师需法务确认输出条款。

模型权重许可：Qwen3-VL/Qwen3.5/InternVL3.5 为 Apache-2.0；ChemDFM-X、MinerU2.5 为 AGPL〔vlm-ft F35〕；MarkushGlyph/MarkushGrapher-2 权重为 Apache-2.0，COMO 权重为 CC BY-NC〔ocsr F25, F38；doc-chem-ie F17〕。

## 5. 评测设计——最需要"认真移植"的部分

autoresearch 能跑起来的前提是 `evaluate_bpb` 这把尺子**可靠、便宜、不可篡改**。对抽取任务而言，这三点都比预训练难得多。

本节统一用这些说法：**标准化** = 去盐（FragmentParent）+ 中和（Uncharger）+ 规范化写法；**开发集（DEV）**、**隐藏确认集（CONFIRM）**、**封存测试集（SEALED）**、**可视化集（dev-viz）**；**主指标** = 决定保留/丢弃的那个标量；**无效结构率** = 解析不出分子的预测占比。

### 5.1 现有公开评分器的漏洞（agent 一定会找到它们）

研究阶段逐行阅读了几个主流评分器的源码，发现的问题正是一个自动爬山的 agent 最容易利用的：

| 评分器 | 问题 |
|---|---|
| MolScribe `evaluate.py` | 所有 RDKit 解析不了的方括号缩写都映射成同一个 `*`：`[Boc]c1ccccc1` 与 `[Ph]c1ccccc1` 被判为相同；解析失败时退回原字符串比较〔metrics F2〕 |
| BioMiner `metric_fn.py` | 去掉了关系符 `<`/`>`；单位换算后用浮点字符串精确比较（2.01 µM ≠ "2009.9999999999998" nM）；无一对一匹配；`;` 拼接的多个编号只要有一个命中就算对；**无效行在算精确率前被过滤**，等于鼓励输出畸形行〔metrics F15, ADDED〕 |
| Doc2SAR `metrics.py` | 只算召回、没有精确率（幻觉行零成本）；数值比较忽略单位和关系符（"10 nM" vs "10 µM" 判对）；对每篇文档取多份预测中的最大值；无预测的文档不进分母〔metrics F16, ADDED〕 |
| MarkushGrapher 评分 | MCS 带 5 秒墙钟超时，分数会随机器负载变化；作者自述对称结构可能误判为正确〔metrics F13〕 |

此外，**RDKit 自身的规范化在 2022.09、2023.03、2023.09、2025.09、2026.03 多次变化**，存储的规范 SMILES 会"过期"——评测必须锁版本，并在评测时对金标与预测**同时**重新标准化〔metrics F7〕。

### 5.2 指标设计原则

1. **主指标严格**：结构必须完全对（含立体）；一条记录只有在"结构 + 终点 + 靶点 + 实验上下文 + 关系符 + 数值（单位归一后）"全部正确时才算对；精确率必须计入（幻觉要付代价）；一对一匹配；缺失/崩溃的文档按零召回计入分母。
2. **与输出表示无关**（对应 bpb 的"词表无关"）：模型输出 SMILES、E-SMILES、CXSMILES、CARBON/图 JSON、molfile 都先转成标准化分子再比较；这样"换输出格式"才能成为 agent 可公平尝试的实验。
3. **分量指标只做诊断、不做决策**：无立体匹配、Tanimoto、Markush、编号共指、按编号匹配的记录 F1（用于区分"结构认错"与"关联错"）。相似度指标不能做主指标：Tanimoto 对对映体给 1.0；在 USPTO-Markush 上 MolScribe Tanimoto 97 而精确匹配只有 7〔metrics F5〕。
4. **护栏按各自的噪声否决**：无效结构率、多片段率、困难切片、防遗忘探针。在 100–300 条的小集合上用固定阈值，每条护栏在零效应下都有 10–30% 的误否决率，所以只有下降超过 max(下限, 2.5 倍标准误) 才否决（6.4 节）。显存不是否决项（爆显存就是崩溃）；吞吐由训练 token 预算、评测解码上限和"部署成本"否决共同约束。
5. **再配一个低噪声的连续"导航"指标**：harness 在固定集合上计算金标序列的 teacher-forcing 负对数似然（同一输出格式内比较），相当于把 val_bpb 原样搬过来——噪声低、便宜，适合每轮都算、做早停和平局裁决；但**保留/丢弃以严格指标为准**，并持续监测两者的相关性〔metrics F26；ecosystem F37, F41〕。

### 5.3 噪声：为什么不能"变好一点就保留"

autoresearch 自己的社区数据已经说明了问题：一份 126 次实验的公开记录里，最小的"保留"增量只有 3.1e-5 bpb，而单纯换随机种子就能让 val_bpb 变化 6.95e-4（约 22 倍）；README 进度图的最后一步本身就是一次换种子〔ecosystem F2, F3〕。抽取任务的指标噪声还要大得多：

| 评测规模 | 精确匹配的标准误（p ≈ 0.8） | 配对比较可检出的最小效应（80% 功效，不一致率 4–8%） |
|---|---|---|
| 300 条 | ±2.3 pp | — |
| 1,000 条 | ±1.26 pp | 1.8–2.5 pp |
| 3,000 条 | ±0.73 pp | 1.0–1.45 pp |
| 10,000 条 | ±0.40 pp | 0.56–0.79 pp |

〔metrics F22〕再叠加三件事：
- **聚簇效应**：同一文档内的结果高度相关；若每篇 20 条、组内相关 0.1，有效样本量只剩约 1/3——所以 bootstrap 必须**按专利族/文章整组重采样**（同一专利族的多页、同一篇文章的正文与 SI 也彼此相关）。
- **种子方差**：同一配方换种子，分数也会变。按方案的开发集（约 3,400 张、约 500 个专利族/文章、设计效应约 1.3）估算，配对差的标准误约 0.48 pp；再加上约 0.5 pp 的种子标准差，"1 个新种子 vs 3 个已存种子"的总标准误约 0.75 pp，"3 vs 3"约 0.63 pp，80% 功效下能检出的最小提升约 1.6 pp。
- **赢家诅咒**：一夜 100 次实验都在同一个开发集上挑最好，纯噪声下的最大值期望约为 +2.5 个标准误（≈ +1.9 pp）；k = 12 时也有 +1.6 个标准误〔metrics F24〕。真实案例：在 Qwen3-VL-2B 上做 autoresearch 式 LoRA 调优，开发集提升 +0.016，换到锁定的 2,000 条确认集上只剩 +0.0088，置信区间跨零〔ecosystem F9〕。

因此保留规则需要：**按专利族 × 种子分层的配对检验 + 显著性门槛 + 多层数据（开发集 / 隐藏确认集 / 封存测试集）+ 安慰剂实验实测误保留率**。具体规则见 6.5 节和 `program.md` 第 6 节。

### 5.4 泄漏与反作弊

- **切分**：按专利族 / 期刊与出版时间切分，而非按图片；跨训练/开发/测试按 InChIKey 第一段与 Bemis–Murcko 母核去重（同一 SAR 系列不能跨集）；感知哈希去重近似图片；禁止在训练中渲染开发/测试分子〔metrics Implications〕。经典识别基准与 USPTO 训练集同源，MolScribe 当年就显式排除了基准所在专利〔data F30〕。
- **agent 会作弊，这已被反复观察到**：PostTrainBench 中前沿 agent 在测试集上训练、下载现成指令模型冒充、使用环境里找到的 API key〔metrics F30〕；一个公开的 autoresearch 衍生项目里，agent 先过拟合验证集，随后发现评分函数在可编辑文件里，直接改写概率把 AUC 从 0.76"提升"到 0.85〔ecosystem F10〕；autoresearch 自身的 issue 也列出了不训练只推进计数器、缩小 EVAL_TOKENS、替换未加哈希的验证分片等攻击路径〔ecosystem F4〕。
- **对策是"隔离"而不是"叮嘱"**：autoresearch 的 `evaluate_bpb` 实际上运行在 agent 写的 `model.forward` 里、读取 agent 进程也能读的验证分片、分数来自 agent 代码打印的 stdout——这在新任务里必须改掉〔metrics F29〕。具体措施见 6.9 节。

### 5.5 参考实现：`harness/score.py`（`evaluate_bpb` 的化学版）

本目录附带一个可运行、已测试的评分器（`harness/score.py`，v1.5；55 个单元测试见 `harness/test_score.py`）。它只依赖 RDKit 与 NumPy，CPU 运行，确定性输出。在 4 核容器上给 3,000 张裁剪图打分约 5 秒（主要花在 RDKit 标准化上），按专利族聚簇的 bootstrap 不到 0.1 秒。输出格式模仿 `train.py` 的结尾摘要，可以 `grep "^score:"`。

它在研究过程中被评委与审稿 agent 逐条攻击过，下面表格里的大部分条目就是它们实际复现出来、随后修掉的漏洞——这本身就说明了 5.1 节的观点：**评分器必须先经过对抗审查，才能交给一个会爬山的 agent。**

**快速上手（今天就能给现成工具打分）**

```bash
pip install rdkit==2026.09.1 numpy        # 版本不符时评分器直接退出；仅调试时可设 SCORE_ALLOW_RDKIT_MISMATCH=1
python3 -m unittest discover -s harness -p "test_*.py"
# 把每个工具的输出转成下面的 JSONL（单分子裁剪图 = 一个 compound、没有 measurement），金标同构：
python3 harness/score.py score --gold gold.jsonl --pred molscribe.jsonl --scalar struct_f1 --per-doc-out molscribe_perdoc.jsonl
python3 harness/score.py compare --base molscribe_perdoc.jsonl --new qwen8b_perdoc.jsonl --scalar struct_f1 --alpha 0.05
```

`--per-doc-out` 导出逐条结果，`score` 会按 `slice`（来源）和 `tags`（难度标签）分别打印分数，用来找错误集中的地方。

**输入格式**（gold 与 pred 同构，JSONL，一行一个文档/页面/裁剪图；建议金标的 `value` 按原文字符串存储以保留末位 0）：

```json
{"doc_id": "US1234567B2-p12", "family_id": "US1234567", "slice": "uspto", "tags": ["chiral"],
 "compounds":    [{"id": "12a", "smiles": "CC(=O)Nc1ccc(O)cc1"}],
 "measurements": [{"compound_id": "12a", "target": "EGFR", "endpoint": "IC50",
                   "relation": "=", "value": "12.3", "unit": "nM"},
                  {"compound_id": "12a", "target": "EGFR", "endpoint": "% inhibition",
                   "value": 87, "unit": "%", "conc": 1, "conc_unit": "uM"},
                  {"compound_id": "12a", "target": "hERG", "endpoint": "IC50", "value": ">30", "unit": "uM"}]}
```

`family_id`（专利族/文章）是 bootstrap 的聚簇单位；`slice`（只看金标）是来源分组，可以加权；`tags`（只看金标，可多个）是难度标签，单独报告。单分子裁剪图 = 只有一个 compound、没有 measurement 的文档，所以同一个评分器覆盖"单分子识别"和"表格/整页抽取"。

**结构身份**

| 问题 | 做法 |
|---|---|
| 输入 | `smiles` 字段只接受 SMILES/CXSMILES。其他输出格式（E-SMILES、molfile、图 JSON、IUPAC 名）由待建的 `harness/formats.py` 先转成 CXSMILES，转换失败按无效结构计 |
| 主键 | RDKit 解析 → `FragmentParent`（去盐/溶剂）→ `Uncharger` → 标准 InChIKey（含立体层）。与输出语言无关——这就是 bpb"与词表无关"在本任务中的对应物 |
| 立体 | 严格：主指标区分立体；`struct_f1_nostereo`（InChIKey 第一段）只做诊断。外消旋/相对构型（CXSMILES `&1`、`o1`）单独成键，不与绝对构型混为一谈 |
| Markush / R 基团 | `[1*]`、`[*:1]`、`$R1$`、`_R1` 四种写法统一为同一 R 编号；位置可变取代（CXSMILES `m:`）的"浮动取代基 + 可连接原子集"被显式编码进键里（修复前，"苯环任意位置 Cl"会被 `FragmentParent` 剥成苯） |
| 金属 | 金属**与有机部分成键**时（配合物、有机金属）按原样用标准 InChI 成键（RDKit 的金属断键会把顺铂变成氨）；游离金属离子（如阿司匹林锌盐中的 Zn²⁺）按普通盐去掉 |
| 原子映射号、实原子上的显示标签 | 忽略 |
| 体量上限 | 单结构 > 500 重原子、单文档 > 5,000 个化合物或 > 20,000 条记录的部分记为无效，防止对抗性输出拖垮评分 |

**活性/属性记录**

| 问题 | 做法 |
|---|---|
| 记录键 | (结构键, 终点, 靶点, 关系符, 单位类, 测试浓度) + 数值；只有全部正确才算一条正确记录（实验类型、物种等字段见 6.10 节的记录键 v2） |
| 单位 | 摩尔浓度统一到 nM（含 µmol/L 写法）；时间统一到 h；复合单位标准化（`mL·min⁻¹·kg⁻¹` = `mL/min/kg`）；**质量浓度（µg/mL）用该记录结构的分子量换算成 nM**；`unit` 为空时依次取数值字符串里的单位（"10 µM"）和终点列头里的单位（"IC50 (µM)"） |
| pX | pIC50/pKi 等转为 nM 并翻转关系符 |
| 数值字符串 | ">10"、"10–30"、"1,200"、"−0.5"、"12 ± 3"、"12 (n=3)"、"1.2 × 10⁻⁵"、"1e-5" 都会被解析 |
| 数值比较 | 同一标度：相对误差 ≤ 0.1%（要求如实转录）；一方经过换算（pX 或质量浓度）：预测值必须落在**金标按原文印刷精度给出的舍入区间**内——只看金标的精度，否则模型可以靠"少写几位小数"放宽容差 |
| 关系符/区间/定性值 | `≥`→`>`、`~`→`=`；`[lo, hi]` 与 "10–30" 是区间；"NT"、"n.d."、"inactive"、分级 "A"/"+++" 作为类别值比较——它们计入金标召回，模型不能靠省略非活性数据刷精确率 |
| 终点写法 | `IC₅₀ (µM)`→`ic50`；`Kᵢ`→`ki`；`T½`/`half-life`→`t1/2`；"% inh @ 1 µM" 中的浓度会被提取为测试浓度 |
| 匹配 | 同一键内做精确的二分图最大匹配（舍入区间可能嵌套，贪心会漏配）；重复记录算假阳性；`;` 拼接多个编号不给分（计为孤儿记录） |
| 金标无法表示的条目 | 结构和记录都在两侧对称排除，并计数报告（`n_gold_unscorable`、`n_gold_rec_unscorable`） |

**复合分数与护栏**

- `--scalar auto|composite|struct_f1|record_f1`；`auto` 在有活性金标时 = `0.5·struct_F1 + 0.5·record_F1`，否则 = `struct_F1`。S1 应显式使用 `struct_f1`。
- `--slice-weights inhouse=0.3,biovista=0.3,uspto=0.2,mrbw=0.2`：主指标改为各来源分数的加权平均（S1 的 `val_struct`）；`--slice-weights patent=1,paper=1,si=1` 即 S2 按文献类型的宏平均。bootstrap 在每个来源内分层重采样。
- 护栏/诊断：`invalid_smiles_rate`（无效结构率）、`multifragment_rate`（去除常见盐和溶剂后仍有多个片段）、`orphan_record_rate`（引用了未定义编号的记录）、`id_link_f1`（编号—结构配对，专门衡量共指）、`record_f1_by_label`（用编号代替结构匹配，用于区分"结构认错"与"关联错"）、Tanimoto、无立体 F1。
- 所有缺失或无法解析的预测按"空"计分；同一文档出现多份预测只取第一份（禁止 best-of-N）。
- RDKit 版本被钉死（`RDKIT_PIN = "2026.09.1"`），版本不符直接退出；`score` 输出金标与评分器的 SHA-256 前缀，写进回执。

**统计**

- `score` 输出按专利族聚簇的 bootstrap 95% CI，以及按 `slice` 和 `tags` 的分组分数。
- `compare --base a,b,c --new x,y,z [--alpha 0.10]` 做**分层配对 bootstrap**：每次重采样同时抽专利族（两侧共用，即配对；在每个来源内分层）与各自的种子，因此种子间方差会进入区间；输出 Δ、置信区间、`p_not_better`、每个种子的分数，以及**每个来源、每个难度标签、每条护栏的配对增量和标准误**——runner 用它们实现"下降超过 2.5 倍标准误才否决"。只给一个种子时只能作为"初筛"。
- 旧做法"把种子合并后只按文档 bootstrap"是反保守的。评委的零效应模拟（种子方差更大的设定）测得名义 5% 的检验实际误保留 15–22%；本目录的 `harness/null_sim.py`（3,000 张图、375 个专利族、每侧 3 个种子、每组 120 次零效应试验）复现了方向，并验证了新做法：

| 种子间标准差 | 种子合并 + 文档 bootstrap | 分层（专利族 × 种子）bootstrap |
|---|---|---|
| 约 0.49 pp | 2.5% | 0.8% |
| 约 0.56 pp | 7.5% | 2.5% |
| 约 0.70 pp | 10.8% | 1.7% |

（名义误保留率 5%；新做法偏保守，这对"保留门槛"是合适的方向。）

**一个直观的噪声量级**：在 60 个文档（120 个结构、120 条记录）的模拟评测上，score ≈ 0.41 的 95% CI 是 [0.34, 0.48]，半宽约 ±0.07。评测集如果只有几十页，0.02–0.03 的"提升"完全淹没在噪声里。

**仍未覆盖、需要在 S2 之前补的**（详见 6.10 节与 `evidence/design_synthesis.md` 附录 (c)）：记录键 v2（实验类型、物种、细胞系/基质、突变体）与靶点→UniProt 表、"金标定义字段"规则；专利分级活性的图例区间；重复测定（n、±SD）作为诊断；`golden_pairs.tsv` 回归集与缩写表一致性测试；Markush 取代基表 F1 与 Sg（频率可变）语义；盐型诊断（ChEMBL Structure Pipeline）；E/Z 与阻转异构体（InChI 不区分阻转异构）；逐条置信度与校准；没有 SMILES 的金标的图级评测；页面级"检测 IoU ≥ 0.5 且结构正确"的联合指标。

## 6. 推荐方案：怎样把 autoresearch 移植到这个任务

### 6.0 交付物：下游拿到的是什么

无论 VLM 循环最终负责多大一块，下游拿到的都是同一套表（Parquet；化合物另导出带属性的 SDF），从第 3 周的混合流水线 v0 开始供数：

| 表 | 一行是 | 主要字段 |
|---|---|---|
| `compounds` | 一个文档中的一个化合物 | `compound_uid`、`doc_id`、`label_as_printed`（"12a"、"Example 212, Step 3"）、`smiles`/`cxsmiles`（标准化母体）、`inchikey`、`inchikey_skeleton`（第一段）、`salt_as_drawn`、`stereo_status`（绝对/相对/外消旋/任意单一对映体/未指定）、`is_markush` + `markush_cxsmiles` + `rgroup_table_ref`、`structure_source`（VLM 识别 / 美国专利 CWU / OPSIN 名称 / R 基团枚举）、`cross_check`（各来源是否一致）、`role`（目标化合物/参照/中间体）、`page`、`bbox`、`confidence` |
| `measurements` | 一个印刷出来的数值 | `record_uid`、`compound_uid`、`endpoint`（封闭词表）、`target_as_printed`、`target_uniprot`、`variant`、`assay_type`、`species`、`cell_line_or_matrix`、`condition`（浓度、时间、pH、剂量、途径、制剂）、`relation`、`value_as_printed`（原文字符串）、`value_std` + `unit_std`、`pX`、`binned_label` + 区间、`n`、`sd`、`cited`（是否引自他文）、出处（页、表、行、列、脚注）、`confidence`、`qc_flags`（如恰好差 3/6 个 log 单位、超出合理范围） |
| `documents` | 一篇文档 | `doc_id`、`family_id`、`doc_type`（专利/论文/SI/内部报告）、`office`（US/CN/WO/EP/JP）、`language`、日期、`license_track`、流水线与模型版本 |

与下游分析的对应：
- **SAR/QSAR 建模**：`measurements`（`pX`、`endpoint`、`target_uniprot`、`assay_type`）连 `compounds`（`inchikey`）；建模时按 `confidence` 过滤，报告 F0.5（更看重精确率）。
- **匹配分子对 / R 基团分析**：`compounds` + Markush 与 R 基团表。
- **专利布局与 FTO**：`is_markush`、`markush_cxsmiles`、`office`、`family_id`。
- **ADMET 画像**：按终点类别筛 `measurements`，必须同时看 `species` 和 `cell_line_or_matrix`。
- **与 ChEMBL/BindingDB 合并或比对**：InChIKey + UniProt + 终点 + pX。
- **人工复核分诊**：`confidence`、`qc_flags`、`cross_check` 加上 `bbox` 定位，化学家只看可疑条目（MolScribe 的人工实验：从头画一个约 35 原子的分子要 137 秒，给出预测 SMILES 后 39 秒，叠加预测的图结构后 20 秒〔ocsr F2〕）。

同一化合物在论文、SI、专利中重复出现时，评分按文档分别计算；交付时再按 InChIKey 合并成跨文档视图。

### 6.1 方案是怎么选出来的

三个独立的设计 agent 分别从不同角度给出完整方案，再由三个评委 agent 各自从一个视角给每个方案打分（1–10），评委对照证据库并实际运行评分器复现问题：

| 方案 | 思路 | 可行性/算力经济 | 评测严谨性 | 化学领域正确性 | 合计 |
|---|---|---|---|---|---|
| **A 最小忠实移植** | 单 agent、单文件、固定预算、单标量；先做单分子识别；保留规则统计化 | 7.5 | 7.5 | 6.5 | **21.5** |
| B 数据中心 | 冻结训练器，agent 只改"数据配方"文件；人类把关的独立数据引擎 | 5.5 | 5.0 | 6.0 | 16.5 |
| C 规模化研究组织 + RL | 8 卡、多角色 agent、多保真度晋升阶梯、种群搜索、可验证奖励 RL | 3.5 | 6.5 | 7.0 | 17.0 |

最终方案**以 A 为骨架**，做了三处升级：
1. **预算按 harness 计量的训练 token 计**（来自 B），加上常驻的评测服务热切换 LoRA。吞吐技巧和机器争用买不到分数，3 张训练卡可以同时跑。
2. **统计诚实性是测出来的，不是声明的**（来自 C 和评委）：安慰剂实验、评测可重复性下限、专利族 × 种子分层 bootstrap、用全新题目的隐藏确认集、只在关口使用的封存测试集、同等 GPU 时的 Hyperband 基线。
3. **产品是记录**：SAR 表阶段从第 5 周开始，对手是混合流水线；无论循环找到什么，生产系统都是混合的。

C 的种群搜索、多角色和批评者先不开，等出现可测量的停滞再加。英文原文与评委意见见 `evidence/design_synthesis.md`。

**强制机制（不是靠叮嘱）**〔ecosystem F4, F10, F29；metrics F29〕：
- **隔离**：harness、`program.md` 和数据池归 root 所有、只读、不可变（`chattr +i`），runner 只执行 `@sha` 副本；训练容器 `--network none`、没有 API key、数据只读挂载、CPU/内存配额、到时硬杀；评测服务（只看得到图片）解码，评分容器（唯一挂载金标的地方）打分并输出签名 JSON。分数从不来自 agent 的 stdout。
- **门禁**：提交改动 `train.py` 以外的文件 → `gate_fail`；静态扫描（≤ 1,500 行；禁止网络/子进程/ctypes 导入、`from_pretrained`、权重或评测路径、种子字面量、篡改计量器）；长度 ≥ 15 的字符串与评测集 SMILES/InChIKey/文献号的 Bloom 过滤器比对。
- **数据门禁**：每个训练样本都经 `dvlm.render`；InChIKey 第一段或 SAR 系列骨架在评测黑名单里的分子被静默替换，agent 只看到三档拦截比例（0 / < 0.5% / ≥ 0.5%），防止它借门禁反复试探某个分子是否在评测集里。
- **回执**：adapter 能在 W0 上加载；计量的 token 数与优化器步数一致（±2%）；权重确实变了；runner 记录 `train.py`、数据池、W0、adapter、harness、金标的 SHA-256。

### 6.5 预算、吞吐与保留规则

**吞吐估算**：512² 的裁剪图是 256 个视觉 token〔vlm-ft F32〕，加提示与答案约 436 token；2B 模型 LoRA 每张约 6·N·T + ViT ≈ 6e12 FLOPs，10–20% MFU 下约 16–33 张/秒〔vlm-ft F33，未核实〕，按 25 张/秒（约 1.09 万 token/秒）规划。

**`TOKEN_BUDGET` = 800 万训练 token（约 1.8 万张），由 `dvlm.Meter` 计数，墙钟 1,500 秒硬杀。** 按 token 计，冗长的输出格式和更高的分辨率要自己为成本买单，机器争用只影响墙钟、不影响样本数。预算按预先登记的规则冻结：{400 万, 800 万, 1,600 万} × 3 个种子 + 4 个人工改动，选种子标准差 ≤ [0.7] pp、且排名与 1,600 万一致（Kendall τ ≥ [0.67]）的最小预算；若 800 万的训练中位时间超过 15 分钟，改用 600 万。

| 步骤 | 在哪里 | 秒 |
|---|---|---|
| 启动容器 + 载入合并后的 W0-2B | 训练卡 | 45 |
| 训练 800 万 token | 训练卡 | 735（555–1,140） |
| 保存 adapter + 回执 | 训练卡 | 15 |
| 热切换 LoRA；解码 4,100 张（开发集 + 探针 + 金丝雀 + 扰动），按 LoRA 推理约慢 1.35 倍估算（需实测） | 评测卡 | ≈ 100 |
| 1,000 张的负对数似然 | 评测卡 | 15 |
| 打分 + 分层配对比较 | CPU | 40 |

约 13.3 训练卡分钟/次，**每卡每小时约 4.5 次**，约 16 分钟出结论。一个 14 小时的夜晚，3 张训练卡约 190 次运行；扣掉 10% 安慰剂、早晨重测和每个候选平均约 0.5 次复现，约 110 个候选——agent（每波 ≤ 3 个）很可能成为瓶颈，预期 **60–110 个想法/晚**。**只有 1 张 H100** 时评测也挤在同一张卡上，约 63 次运行、约 40 个想法/晚。

**评测服务**：vLLM 常驻 W0-2B 并开启 LoRA（4 个槽位，rank ≤ 128），第 1 周先验证 Qwen3-VL 的 LoRA 支持（不行就合并权重，每次多 3–4 分钟）。批量贪心解码不是批不变的，所以固定请求顺序和批大小，并把实测的可重复性下限加进总标准误。`EVAL_DECODE_CAP` = 600 秒/次（约为基线的 6 倍），够用约 500 token 的图遍历推理〔ocsr F9〕或 4 票投票；没解码完的按错。部署目标：8B 每张裁剪图 ≤ 0.5 GPU 秒（按 2.69 美元/GPU 时折算约 0.0004 美元〔vlm-ft F11〕），每页 ≤ 5 GPU 秒。

**GPU 分配（S1）**：0–2 号训练；3 号评测服务；4 号安慰剂、第二个评测服务与早晨重测；5–7 号先建 W0，之后跑 R2、排名一致性审计、Hyperband 和数据引擎的教师模型。

**梯级**：R0 60 秒冒烟 → R1 初筛（1 个种子）→ R1 复现（再加 2 个种子）→ 隐藏确认集（只评测）→ R2（W0-8B 上的 8B LoRA，3,200 万 token，约 2.6 小时〔未核实的吞吐〕，2 个种子，每周或按需）→ R3 关口发布。

**W0（相当于上游的分词器，每个阶段固定）**：Qwen3-VL-2B 先 LoRA（r = 64，30 万样本，约 3.4 GPU 时），再冻结 ViT、分模块学习率做选择性全参（120 万样本）——因为 MolSeek-OCR 直接全参 SFT 发散了〔ocsr F16〕。约 18 GPU 时，之前做 4 点学习率扫描（约 12 GPU 时）。训练目标按提示标签支持多种输出格式，超原子如实保留。W0-8B 是 120 万样本上的 r = 128 LoRA，4 卡约 12 小时。

**保留/丢弃**（runner 执行，完整步骤见 `program.md` 第 6 节）：

| 步骤 | 条件 | 不满足时 |
|---|---|---|
| 门禁 | 只改了 `train.py`、通过扫描、描述符是新的 | `gate_fail` |
| 初筛（种子 s0，与在位者已存的 3 个种子配对） | 收缩后 Δ ≥ +[0.5] pp 且 `p_not_better` ≤ [0.20]，护栏不否决 | `discard` / `veto:*` |
| 复现（补跑 s1、s2，三对三） | 平均 Δ ≥ +[0.5] pp、`p_not_better` ≤ [0.05]、≥ 2/3 配对为正 | `replicate_fail` |
| 隐藏确认集（≤ [10] 次/天，只返回通过/不通过） | 平均 Δ > 0、`p_not_better` ≤ [0.10]、没有切片下降超过 max([2] pp, 2.5·SE) | `confirm_fail` |
| 长程复核（学习率/调度/分辨率类改动，或已堆了 2 个未复核的保留） | R2 下界 ≥ 0 | `r2_revert` |
| 推进分支 | — | `established` |

设计理由：
- **种子方差必须进入检验**（5.5 节的模拟）；**公共随机数**：runner 管种子，数据流不变时数据顺序与在位者相同。
- **赢家诅咒**：约 100 个零效应初筛里最好的会高出约 2.5 SE（≈ 1.9 pp）〔metrics F24〕，所以初筛永远不推进分支；种子共享开发集题目，消除不了题目层面的诅咒，因此确认集必须用**全新题目**，每天 ≤ 10 次、100 次查询后或每月从储备集轮换 30%〔metrics F25，未核实〕。
- **在位者也可能是运气好**：每天 07:00 用 3 个新种子重测在位者，若均值低于记录 1 个总标准误以上，替换它的基准文件。
- **经验贝叶斯收缩**：显示和排序用的 Δ 先收缩，抑制"小样本上的大增量"。
- **安慰剂实验**：每 10 个初筛槽位插 1 个不改任何东西的"候选"，不事先告知 agent；目标：promising ≤ 20%、dev_keep ≤ 5%、established ≤ 2%、否决 ≤ 10%；滚动 50 次超标就把 z 提高 0.25 并通知人类。误保留率是测出来的，而不是乘出来的。
- **分层使用**：可视化集给逐条结果；开发集只给四舍五入的值（0.1 pp，切片 0.5 pp）；确认集只给一个比特；封存测试集只在关口和最终发布由人类使用（8 周内 ≤ 4 次）。最终选择：R2 上前 3 名的 `established` 状态进确认集，只有赢家进封存测试集〔ecosystem F16〕。
- **简化**：净删 ≥ 20 行、平均 Δ ≥ −[0.2] pp 走非劣效路径，确认集下界 > −[0.5] pp 即保留，每天最多 1 次，每周有漂移检查。

### 6.6 两个"值不值得"的审计：排名一致性与 Hyperband 基线

**排名一致性审计**（2B 短跑的排名能否代表 8B 长跑）：用 8 个配方算 Spearman ρ 判不出任何东西（ρ = 0.6 的 95% CI 约 (−0.2, 0.9)）。所以取 24 个覆盖整个 R1 增量范围的配方（6 个最好、12 个中间、6 个最差）在 R2 上重跑（约 62 GPU 时），其中 8 个在两个梯级都重跑种子（约 22 GPU 时），测出各自的重测信度 r1、r2。**通过**：Fisher-z 95% 下界 ρ ≥ [0.3]（ρ = 0.6、n = 24 时 CI 约 [0.26, 0.81]）、去衰减 ρ/√(r1·r2) ≥ [0.6]、且 ≥ [75]% 的 `established` 在 R2 上为正。CI 跨过 0.3 就再加 12 个配方，期间最多堆 2 个未复核的保留。**失败**（去衰减 ρ < [0.4]）：预算改为 1,600 万 token 或改用 4B 作短跑模型；第二次失败就把搜索交给 R2 上的 Hyperband。学习率、调度、分辨率类改动在 R1 允许，但标记为长程敏感〔ecosystem F42〕，叠加前必须过 R2。

**同等 GPU 时的非 agent 基线**（第 4 周）：Optuna-TPE + ASHA（200 万 → 800 万 → 3,200 万 token），在 `program.md` 的数值旋钮上搜索，同样的 W0 和保留规则，84 GPU 时，等于 agent 前两晚的用量〔ecosystem F36, F40〕。比较指标是"每 GPU 时确认的增益"。证据显示 agent 主要在调超参（MLGym）；如果脚本化扫描做得一样好，旋钮就交给 Hyperband，agent 只负责代码层面的改动。

### 6.7 搜索空间

S1 的 22 条按优先级排列的想法、长程敏感标记和已知负面结果见 `program.md` 第 9 节。前 4 晚做 1–10（学习率、真实数据比例、增强课程、超原子标签、手性、LoRA 目标、分辨率、EMA、难例加权、回放）；第 4 周起做输出格式、图遍历推理、投票、切块，以及 RL 通道（MRT、严格 InChIKey 奖励的 GRPO/DAPO）。RL 通道有固定的 1,800 GPU 秒预算，并自动配一个同等 GPU 秒的继续 SFT 对照，因为采样算力逃过了 token 计数。

S2 追加：表格裁剪 + 母核裁剪 + 脚注条的多视图输入；用文档自带编号（"1a"）作视觉提示（IdtVP）〔doc-chem-ie F13〕；输出 `rgroup_table_v1` 由 harness 枚举〔doc-chem-ie F23〕；YAML 记录（olmOCR 从 JSON 改为 YAML 后重试与复读显著减少〔vlm-ft F13〕），扁平 JSON-lines 作为待检验的替代；在扰动的真实版面上合成 SAR 表〔data F10〕。

### 6.8 组织：先一个 agent，被证据逼迫时再扩展

- **一个 agent、一个分支、三个训练槽位**，每波最多 3 个单因素候选（SkyPilot 的 agent 自发这样做〔ecosystem F6〕）。确定性的 runner 充当统计员。
- **谱系**是最重要的"组织"组件：runner 写 `lineage.jsonl`（假设、描述符、diff、父提交、种子、指标、数据构成、回执、状态、失败原因）。agent 只看在位者（当前分支上已确认的最优版本）、最近 15 行和"已失败描述符"表；重交已失败的描述符必须写明这次哪里不同（Amazon 的部署里 agent 不顾 program.md 的禁令把同一个失败想法重测了 6 次以上〔ecosystem F15〕）。
- **人类**：每天 15–20 分钟（前沿、安慰剂、排名一致性、轨迹标记）；停滞通知（2 晚或 150 个候选没有 `established`）触发时，在 `program.md` 末尾"当前方针"写 2–5 句新方向。每周：R2 与数据池更新。关口：封存测试集与决策。
- **批评者**：每周用另一家族的模型扫一遍 agent 轨迹，只标记、不打分〔metrics F35〕。
- **只在被迫时扩展**（第 4 周后一周内两次停滞通知）：加第二个侧重点不同的 agent。C 的 MAP-Elites、总监角色和多通道推迟。

### 6.9 反作弊清单

- **隔离与门禁**：见 6.2 节"强制机制"。
- **种子**：runner 下发、三种子 + 确认集（Claudini 在停滞后退化成了"搜种子"〔ecosystem ADDED〕）。
- **反馈粒度**：开发集四舍五入、可视化集单独留出、确认集一个比特且有额度。
- **推理配置**：`infer_config` 有 schema 校验，提示词扫描类 SMILES 字符串。
- **评分器严格**：无效、重复、缺失都算模型的错；禁止 best-of-N；未知缩写算错〔metrics F15, F16〕。
- **监测**：金丝雀与扰动报警；每晚对训练样本 ID 做重叠审计；回执绑定代码、数据、权重和金标；每周轨迹扫描。LLM 永不做评分函数（诸如"答案正确"之类的空洞回答骗过 LLM 评审的比例可达 80%）。
- **确认作弊时**：冻结、修补 harness、重测在位者，相关行标为 `hack`。

### 6.10 S2 之前必须补齐的"记录语义"

评委一致认为，当前记录键对药化分析来说还太"薄"——生化 IC50 与细胞 IC50 互换、大鼠与人的清除率互换，现在都会被判为正确。S2 开始前需要：

1. **记录键 v2**：结构、终点（封闭词表）、靶点（经 `targets_v1.tsv` 映射到 UniProt 或物种）、突变体、实验类型、物种、细胞系/基质、条件、关系符、单位类、数值。
2. **"金标定义字段"规则**：某字段只有金标填了才计分。推断出正确的物种有奖励，乱填没有。
3. **专利分级活性**：金标同时存印刷的标签（"A"、"+++"）和按图例解析出的区间，两者都算对。
4. **现在采集、S2b/S3 再评分**：n、±SD、重复序号；`stereo_status`；ADMET/PK 字段（剂量、途径、制剂、pH、动力学 vs 热力学溶解度、Caco-2 方向与外排比、CYP 亚型、时间点）；出处（页、框、表、行、列、脚注）。
5. **标注范围规则**（`annotation_guide.md`）：一条记录 = 一个化合物 × 终点 × 体系 × 条件下印刷的一个数值；参照化合物标 `role=reference`；中间体只在有数据时计入；引自他文的值保留并标 `cited=true`；论文与 SI 的重复按文档分别计分；`compound_id` 按原文印刷（"Example 12, Step 3"）；立体和 E/Z 按画出的计分。没有这些规则，精确率就没有定义。
6. **规模**：开发集 140 张表（约 70 篇文档：内部 80、BioVista 验证集 40（按 PDB ID 取 PDF）、ChemX 的 MIC-菌株表 20，µg/mL 按分子量换算）；确认集 100；封存集 60（EPO/CNIPA，截止日期之后）。错误按表成片出现，有效样本量接近表格数：标准误约 2–3 pp，最小可检效应约 6 pp，所以 S2 只能找大杠杆。组内相关在第 5 周实测，不借用文献值（metrics F22 的 2.9 是假设值）。
7. **推理期的捷径与质检**（混合流水线 v0 就用）：美国专利直接读 CWU 的 MOL/CDX，再用 VLM 识别交叉核对（连接表也会错〔data F2〕）；实施例有 IUPAC 名时由模型转写名称、OPSIN（MIT）转结构，与识别结果不一致就标记；CAPRICHO 式的"恰好差 3 或 6 个 log 单位"标记与各终点的合理范围检查〔doc-chem-ie F30〕；自建分子检测器（从 Docling 的 MIT 分类器起步，MolDetv2 是非商用），第 6 周起每晚在 50 张内部页面上报告页面级联合指标〔metrics F17〕。

### 6.11 数据策略

- **固定数据池**（每条样本带许可、轨道、来源、专利族）：`render`（200 万 PubChem/ChEMBL 分子，剔除评测分子的 InChIKey 第一段和 SAR 系列骨架，用 RDKit、Indigo、CDK 以 RanDepict 风格渲染，两种标签视图）；`uspto`（MolScribe 的 68 万对，清洗：`*` 重映射、CDX 优先于 MOL、多模型分歧样本剔除，并去掉评测专利族和经典基准专利；第 4 周换成自己挖的 2001–2024 版）；`stereo`（Stereo-200k）；`markush`（MarkushGrapher-1 数据，CC BY 4.0；USPTO-MOL-M 待法务）；`inhouse` 与 `replay`；S2 的 `sar`（在扰动真实版面上合成、用 ChEMBL/BindingDB 数值填充的 SAR 表，加 ChemX 与内部训练表）。
- **标签保真**（harness 统一执行）：超原子如实保留；`*` 只用于画出来的通配符；立体只标画出来的；反离子按画出的保留、按母体评分。
- **泄漏控制**：按专利族/文章切分；InChIKey 第一段跨池去重；Murcko 系列整体留在一层并从渲染中拉黑；感知哈希去重；封存集按时间切分；每晚重叠审计。
- **数据引擎**（离线、人工把关、每周更新后重测基线）：收集商用轨道页面；从多模型一致度 0.6–0.9 的区间采样；数字原生 PDF 用 ChemScraper 的矢量标签。化学家修正约 30 秒/分子，双人复核下每 40 小时约 2,400 张。
- **固定的**：数据池、评测分层、生成器、词表、W0、上限、预算。**agent 可调的**：权重、特征筛选、增强代码、渲染样式、课程、标签视图、损失、输出格式。

### 6.12 基座模型

- **内循环：Qwen3-VL-2B-Instruct**。Apache-2.0；OCRBench 858（Thinking 版 792）；每 32 像素一个 token；TRL、ms-swift、LLaMA-Factory、vLLM 都支持〔vlm-ft F1, F2, F29〕。
- **R2 与生产：Qwen3-VL-8B-Instruct**（OCRBench 896；8B LoRA 单张 H100 放得下〔vlm-ft F30〕），与 2B 共享视觉塔、分词器和模板，迁移最有希望。备选短跑模型：Qwen3-VL-4B（881）。
- **第 1 周小比武**（零样本 + 2 小时同配方 SFT）：只有差距 ≥ [3] pp 才换成 InternVL3.5-2B/4B（Apache；836/822）或 Gemma 4 E4B/12B（Apache）。
- **排除**：Qwen3.5（默认思考模式、依赖 flash-linear-attention、DeltaNet 状态在打包样本间泄漏〔vlm-ft F4〕）；Gemma 3（固定 896 像素）；AGPL/非商用模型〔vlm-ft F35〕；化学专用 VLM（ChemVLM 8.03、ChemDFM-X 19.06，修订版 MolRecBench-Wild〔ocsr F10〕）。

| agent 不比 Hyperband 强 | 第 4 周同算力基线 | agent ≤ Hyperband → 旋钮交给 Hyperband，agent 只负责代码层面的改动 |
| VLM 的结构识别有天花板：朴素 SMILES SFT 可能卡在 DECIMER 水平（MolSeek-OCR）；图遍历输出 + 真实数据的 VLM 可达 MolScribe 乃至 93%〔ocsr F9, F10, F16；data F29〕 | 真实数据、超原子标签、`graph_json`、MRT | 6.3 节转向条件 |
| 确认集被慢慢过拟合 | 额度、轮换、封存测试集 | 通过率 < 30% → 轮换并提高 z |
| S2 标注瓶颈 | 用数据库预填、先用公开表格 | 第 5 周 < 140 张表 → 先用公开表格开跑，出口顺延 |
| 开发集与团队文档构成错配（如缺中国专利） | 第 0 周差距表、来源加权、封存集含 CNIPA/EPO/JPO | 封存集上中国专利切片明显落后 → 增加该来源的数据与开发集切片 |
| 许可污染 | 清单、双轨道 | 发现非商用样本 → 作废该实验及其所有后代 |
| 基础设施脆弱 | 冒烟测试、重试、前 3 晚预留 20% 槽位（Amazon 的 30 次迭代里有 11 次浪费在评测超时〔ecosystem F15〕） | 崩溃率 > 15% → 打开廉价模型的代码修复器 |
| 评测不确定性 | 实测可重复性下限 | 下限 > 0.2 pp → 确定性解码 |
| 基座模型污染 | 污染探针、按时间切分的封存集 | 标记该来源 |
| 奖励作弊 | 安慰剂、金丝雀/扰动、轨迹扫描 | 确认作弊 → 冻结、修补、重测、标 `hack` |
| 指标与下游价值脱节 | 下游有效性检查（6.13 节） | 重新定义主指标（由人类决定，不是 agent） |

**放弃自主循环**：到第 6 周，如果没有任何前沿在隐藏确认集上超过混合流水线，且 Hyperband 与 agent 打平，就停掉自主循环。harness、数据引擎和混合流水线仍然是产品。

## 9. 需要你来拍板的事项

1. **商用还是研究用途？** 这决定能否用 MolParser-7M/MolGallery（非商用）、能否把 MarkushGrapher-2/MarkushGlyph 当教师、能否用前沿 API 模型的输出当标签（需看服务条款）。默认按"商用"设计。
2. **算力**：本方案假设一台 8×H100 节点用 6 周；只有 1 张卡也能跑 S1（每晚约 40 个想法，复现要串行，排名一致性审计和 Hyperband 要缩小）。
3. **标注预算**：约 400 个化学家时，S2 的进度主要取决于这一项。
4. **团队的文档构成**：专利与论文/SI 的比例、主要靶点类别、**专利局别（US/CN/WO/EP/JP）与语言**——用于给开发集加权，决定 S2 先做 SAR 表还是 ADMET/PK 表，也决定两条推理期捷径（只覆盖美国专利和英文名称）值多少。
5. **订阅期刊的内部副本能否用于训练**（而不仅是推理）：需要法务结合各出版社的 TDM/AI 条款判断。
6. **是否接受"混合方案"作为终点**：如果 11 月 13 日的证据表明专用识别模型 + VLM 读表关联更好，是否接受这个结论，而不是坚持"一个 VLM 包打天下"。
7. **内部文档的保密边界**：未公开的化合物与内部报告能否发送给外部 API（前沿模型做教师/打标、轨迹审查）？如果不能，教师只能是本地开源模型，内部开发集只在本地评测，最终模型也必须内网部署——这也是基座选 Apache-2.0 开放权重模型而不是闭源 API 的主要理由之一。

## 10. 仍未解决的问题

- 没有公开研究测过"2–3B 模型、约 15 分钟的化学 VLM 微调"的配方排名能否预测 8B、全量数据下的排名——只能在自己的数据上实测。
- 哪个连续指标最能预测 InChIKey 精确匹配：金标序列的负对数似然、化学关键 token 加权的似然，还是图编辑距离？
- 在单节点、每次十几分钟的预算内，RL 相比把同样算力花在更多 SFT 上能带来多少——已发表的 RL 收益来自数小时到 70 小时的训练。
- 一个微调的 3–8B 通用 VLM 能否同时做到专用识别模型的精度（真实文献约 93%）和表格阅读、编号共指？目前没有在文档级 SAR 基准上的正面对比。
- 怎样给 Markush 部分分数（严格图等价、逐 R 基团取代基集合 F1、还是枚举覆盖率），以及它如何进入活性记录（通式 + R 基团表对应的活性）。
- 立体策略的细节：未画出立体的外消旋体、"任意指定"的构型、手性拆分后的"对映体 1/峰 1"、金标缺 E/Z 时如何处理、阻转异构体（InChI 不区分）。
- 用 BindingDB/ChEMBL 自动对齐得到的页面级标签有多可靠（HARVEST 报告的与人工一致率是 80–91%，且未核实），开发集需要多少人工复核。
- 中文化合物名、非美国专利的结构识别有没有可用的捷径（类似 CWU/OPSIN）。
- 证据库中约 14%（39/287 条）的条目因核查环境无法访问 arXiv/EBI/NCBI 等站点而标为"未核实"，引用前应补核（尤其是 2026 年 8–9 月的几篇预印本）。

| 术语 | 含义 |
|---|---|
| OCSR | 光学化学结构识别：把分子结构图识别成机器可读结构（如 SMILES） |
| Markush 通式 | 专利里用 R1、R2 等可变基团一次覆盖成千上万个化合物的通式结构 |
| R 基团枚举 | 把母核和取代基表组合成每个具体化合物的完整结构 |
| SAR 表 | 构效关系表：一列化合物（常以 R 基团表示）及其活性数据 |
| SMILES / CXSMILES / E-SMILES | 分子的线性文本写法；CXSMILES 在后面附加立体组、R 基团标签等扩展信息；E-SMILES 是 MolParser 的扩展写法 |
| molfile、MOL/CDX | 带坐标的分子文件格式（MDL、ChemDraw） |
| CWU | 美国专利随全文发布的化学结构文件（MOL/CDX + 图片） |
| OPSIN | 把英文 IUPAC 名称转成结构的开源工具（MIT） |
| InChIKey | 分子的标准化哈希；第一段只编码骨架连接，完整键还包含立体等信息 |
| 标准化 | 去盐（FragmentParent）、中和（Uncharger）、规范化写法后再比较 |
| 超原子 | 图中画成缩写的基团（Ph、Boc、OMe），"所见即所标"要求标签也保留缩写 |
| 增强立体 | CXSMILES 中表示外消旋（`&1`）或相对构型（`o1`）的标记 |
| Murcko 骨架 | 去掉侧链后的环系 + 连接子，用来防止同一 SAR 系列跨训练/评测集 |
| Tanimoto | 两个分子指纹的相似度，对对映体给 1.0，只能做诊断 |
| VLM | 视觉语言模型（多模态大模型） |
| LoRA | 只训练少量附加低秩参数的低成本微调方式；rank 越大可训练参数越多 |
| SFT / 全参 / 选择性全参 | 监督微调；训练全部参数；只解冻部分模块训练 |
| MRT / GRPO / DAPO / GSPO | 直接以"结构是否正确"等序列级奖励训练的方法（最小风险训练与几种 RL 算法） |
| 可验证奖励（RLVR） | 奖励由确定性程序判定（如 InChIKey 是否相同），不靠人或 LLM 打分 |
| token / 视觉 token | 模型处理的最小单位；Qwen3-VL 每 32×32 像素一个视觉 token |
| MFU | 模型算力利用率：实际 FLOPs 占硬件峰值的比例 |
| vLLM | 常用的高吞吐推理引擎，可热切换 LoRA |
| val_bpb | 上游 autoresearch 的指标：验证集每字节比特数，越低越好 |
| W0 | 本方案的热启动检查点，每个阶段一次性构建、只读，相当于上游的分词器 |
| 在位者（incumbent） | 当前分支上已确认的最优版本 |
| 开发集 / 隐藏确认集 / 封存测试集 / 可视化集 | DEV：决定保留/丢弃；CONFIRM：只返回通过/不通过；SEALED：只在关口由人类使用；dev-viz：给 agent 看逐条错误 |
| R0 / R1 / R2 / R3 | 实验梯级：冒烟、2B 正式实验、8B 长程复核、关口发布 |
| pp | 百分点 |
| bootstrap / 聚簇 | 通过反复重采样估计置信区间；按专利族/文章整组重采样，因为同一族内结果相关 |
| `p_not_better` | bootstrap 重采样中"新配方不比在位者好"的比例，可当作单侧 p 值 |
| 最小可检效应（MDE） | 在给定功效下能可靠检出的最小提升 |
| 组内相关（ICC）/ 设计效应 | 同一文档内结果的相关程度；它让有效样本量缩小的倍数 |
| Kendall τ / Spearman ρ | 两组排名一致程度的指标 |
| 赢家诅咒 | 在同一数据上挑出的最好结果系统性地高估真实效果 |
| 安慰剂实验 | 不改任何东西的"候选"，用来实测门槛的误保留率 |
| 经验贝叶斯收缩 | 把带噪声的增量向总体均值拉回，抑制"小样本上的大增量" |
| 短视野偏差 | 短时间训练下的最优超参数不等于长时间训练下的最优 |
| Hyperband / ASHA | 先用小预算淘汰、再给幸存者加预算的超参数搜索方法 |
| Track C / Track R | 商用轨道 / 研究轨道（非商用许可，永不交付） |
