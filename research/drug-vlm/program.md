# drug-vlm autoresearch —— 阶段 1：化学结构识别（草案 v0）

> 这是给 agent 的研究方针，对应上游仓库根目录的 `program.md`。**人类负责迭代这个文件，agent 只读。**
> 它假设第 0 阶段的基础设施已经就绪（见 `README.md` 第 6 节）：`prepare.py`（数据池、评测分层、S0 热启动）、
> `runner.py`（门禁、容器、回执、results.tsv 的唯一写入者）、`harness/evaluate.py`（固定推理）、
> `harness/score.py`（固定评分）、`harness/keep_rule.py`（保留/丢弃判定）以及 agent 唯一的提交入口 `run.sh`。
> 方括号里的数字是第一周校准（见 `README.md` 6.4 节）之前的默认值，校准后由人类改写。

这是一个让 LLM 自己做研究的实验：在固定的数据、固定的评测和固定的算力预算下，
把一个视觉语言模型微调得更会"读"药物研发文献和专利里的化学结构。

## 当前阶段与目标

**阶段 S1：单分子裁剪图 → 化学结构。** 输入是一张只含一个分子（或一个通式）的裁剪图，输出是结构。
主指标是 **`val_struct_f1`**（越高越好）：评测集 DEV 上，标准化母体分子（去盐、中和）的**带立体信息的标准 InChIKey** 精确匹配的 F1。
你的模型用什么语言输出结构（SMILES、CXSMILES、molfile、原子/键 JSON、先图遍历再给答案……）都可以，评测会先把它转成分子再比较——
就像 `val_bpb` 与词表大小无关一样，这个指标与输出表示无关，所以"换一种输出表示"是可以公平尝试的实验。

Markush 通式、页面级抽取、活性数据表格属于后续阶段。在 S1 中，Markush（IP5-M/M2S）只作为诊断列出现，不参与保留/丢弃。

## 准备工作（Setup）

与人类一起完成：

1. **约定运行标签**：基于日期，例如 `oct20-s1`。分支 `autoresearch/<tag>` 必须不存在。
2. **建分支**：`git checkout -b autoresearch/<tag>`。
3. **通读这些文件**：
   - 仓库根目录 `README.md`（autoresearch 原始范式）；
   - `research/drug-vlm/README.md`（本项目的调研报告：为什么这么设计、文献里哪些方向有效、哪些已知无效）；
   - 本文件；
   - `prepare.py`：常量、数据池接口 `load_pool()`、评测分层。**只读。**
   - `train.py`：你唯一可以修改的文件。
   - `harness/score.py`：只为理解指标而读。**只读。**
   - `lineage.jsonl` 与 `failed_ideas.tsv`（如果已有）：以前试过什么、为什么失败。
4. **确认环境就绪**：`prepare.py --check` 通过（数据池清单与哈希、S0 热启动检查点存在）；`./run.sh --smoke` 能在约 60 秒内跑通并报告吞吐。任何一项不满足，告诉人类，不要自己修。
5. **基线**：第一次提交永远是**未修改的 `train.py`**，runner 会自动跑 3 个种子作为在位者（incumbent）。
6. **向人类确认后开始。**

## 你能做什么、不能做什么

**可以：** 只修改 `train.py`。文件内一切都可以改：
- LoRA / 部分解冻 / 选择性全参，冻结哪些模块，各模块各自的学习率与调度；
- 数据池采样权重、课程（由易到难）、数据增强、用 `load_pool("render_smiles")` 暴露的 SMILES 现场渲染新图；
- 标签视图（超原子如实保留 vs 展开）、输出表示、提示词模板；
- 损失函数：包括在**训练池**上使用 `harness.reward` 中公开的奖励函数做最小风险训练（MRT）或 GRPO 类强化学习；
- 推理配置 `/out/infer_config.json` 中允许的字段：`prompt`（≤ 2,000 字符）、`output_format`（必须属于 `prepare.OUTPUT_FORMATS`）、`max_pixels`（≤ 上限）、`decoding`（`greedy`，或 `vote` 且 k ≤ 8）、`max_new_tokens`（≤ 上限）。

**不可以：**
- 修改 `train.py` 以外的任何文件（runner 的门禁会拒绝，记为 `gate_fail`）；
- 联网、下载任何检查点或数据集、新增依赖（只能用 `pyproject.toml` 里已有的包）；
- 读取评测路径、在代码里写入任何 SMILES/InChIKey/文献号字面量（静态扫描会拒绝）；
- 设置随机种子（种子由 runner 通过 `DVLM_SEED` 下发，用于和在位者配对比较）；
- 绕过 `prepare.load_pool()` 读数据（训练样本数由它计数）；
- 试图影响评测：评测在另一个容器里用固定代码加载你的 adapter 和 `infer_config.json`，分数从不来自你的 stdout。

**预算（固定，在 `prepare.py` 里）：**
- 每次实验最多训练 **[20,000] 个样本**（经 `load_pool()` 计数），且训练墙钟 ≤ **[1,500] 秒**（不含启动）；先到者为准。按样本计而不是只按时间计，是为了不奖励"减小 batch 多跑几步"这类与硬件绑定、无法迁移的技巧。
- 评测墙钟上限 **[360] 秒**，没解码完的样本按错误计——所以投票、长思维链这类推理开销会自动付出代价。
- 显存是软约束：峰值不要超过 **[75] GB**。
- 每次实验从同一个 **S0 热启动检查点**开始（相当于上游的分词器：一次性构建、只读）。你优化的是"在 S0 之上再训练一小段"的配方。

**简洁性准则（照搬上游并量化）：** 同等条件下越简单越好。
- 删掉 ≥ 20 行代码、分数变化 ≥ −0.2 个百分点（pp）：在通过确认集后保留——这是简化的胜利。
- 新增 > 60 行代码：所有保留阈值翻倍。
- 为了 < 0.5 pp 引入一套脆弱的特判（正则后处理、针对某类图的硬编码规则）：不值得。

## 指标、护栏与你能看到什么

- **主指标** `val_struct_f1`：DEV 约 [3,000] 张裁剪图，来自真实论文、专利与内部文档，按文章/专利族划分。你只看到**四舍五入到 0.1 pp 的聚合值**和各切片的增量。
- **一票否决的护栏**（即使主指标上升也不保留）：
  - 无效结构率上升 > 0.5 pp；去盐后仍为多片段的预测比例上升 > 0.5 pp；
  - 任一切片（手性、缩写、> 50 重原子、扫描/低分辨率、内部文档）下降超过 1.5 pp **且**超过 2 倍标准误；
  - 300 条通用文档 OCR/表格探针下降 > 3 pp（防遗忘）；
  - 评测超时。
- **只做诊断、不做决策**：无立体 F1、Tanimoto、编号—结构配对 F1、Markush 精确匹配、扰动副本上的差距（记忆化报警）。
- **错误分析**：用 `dev-viz`（约 200 张、单独留出、可以看到逐条预测与金标）。DEV 本身不提供逐条结果。

## 记录（runner 负责，你只读）

`results.tsv`（制表符分隔，不入库）由 runner 写，列为：

```
commit	stage	seeds	dev_score	delta	ci90_lo	ci90_hi	p_not_better	status	invalid_rate	multifrag_rate	worst_slice_delta	probe_delta	samples_seen	train_s	eval_s	peak_vram_gb	description
```

`status` 取值：`baseline`、`discard`、`PROMISING`、`DEV_KEEP`、`ESTABLISHED`、`confirm_fail`、`veto:<护栏名>`、`crash`、`gate_fail`、`timeout`。

`lineage.jsonl` 记录每次实验的假设、diff 摘要、父提交、各项指标、状态与失败原因；`failed_ideas.tsv` 以规范化的"改动描述符"（如 `lr=2e-4|lora=attn|r=64`）为键。`run.sh` 会拒绝与已失败描述符重复的提交，除非你的假设写明了这次有什么不同。

## 保留 / 丢弃（由 `keep_rule.py` 判定，你按结果操作）

1. **初筛 SCREEN**（种子 0，与在位者的种子 0 配对比较）：Δ ≥ +[0.5] pp、`p_not_better` ≤ [0.25]、无护栏否决 → `PROMISING`；否则 `discard`。
2. **复现 REPLICATE**（runner 自动补跑种子 1、2）：分层 bootstrap（同时重采样专利族与种子）下，平均 Δ ≥ max([0.6] pp, 2·σ_seed/√3)、`p_not_better` ≤ [0.05]，且三个种子各自都优于在位者对应种子 → `DEV_KEEP`。
3. **确认 CONFIRM**（runner 在隐藏的确认集上评测这三个 adapter，你只看到通过/不通过）：平均 Δ > 0、`p_not_better` ≤ [0.10]、没有切片下降 > 2 pp → `ESTABLISHED`。
4. **只有 `ESTABLISHED` 才推进分支**：这次提交成为新的在位者，它的三个种子结果成为新的比较基准。
5. 其他任何结果（`discard`、`confirm_fail`、`veto:*`、`crash`、`gate_fail`、`timeout`）：`git reset --hard` 回到在位者。`confirm_fail` 的想法会以 "dev-only" 标签留在谱系里，以后可以和别的想法组合再试。

为什么这么麻烦：这个指标的噪声比 `val_bpb` 大一个数量级以上；一夜几十次实验在同一个开发集上挑最好的，纯噪声也能"找到"约 1 pp 的提升。上游社区已经多次把"换随机种子"记成改进。
runner 还会做两件你看不到的事：每天早上用新种子重测在位者（如果它当初是运气好，就替换掉它的基准）；以及偶尔插入"安慰剂"实验来实测这套门槛的误保留率。

## 实验循环

实验在专用分支上进行（如 `autoresearch/oct20-s1`）。

**永远循环（LOOP FOREVER）：**

1. 看 git 状态：当前在哪个提交（应当是在位者）。
2. 读 `lineage.jsonl` 里在位者那一行、你自己最近 15 行、以及 `failed_ideas.tsv`。
3. 选一个想法，直接改 `train.py`。一次只验证一个假设。
4. `git commit`。
5. `./run.sh "假设：……；预期：……"`，等它返回。
6. 如果是 `crash`：读日志尾部。拼写错误、少导入这种小问题就修好重跑（用 `./run.sh --smoke` 先试）；想法本身行不通就放弃，runner 已经记为 `crash`。
7. 按上一节的结果操作：`ESTABLISHED` 则保留提交；其余一律 `git reset --hard` 回到在位者。
8. 在 `notes/`（不影响评测）里用两三句话写下你从这次结果里学到了什么，供下一轮参考。
9. 回到第 1 步。

**超时：** 单次实验（训练 + 评测）超过 [2,400] 秒会被 runner 杀掉并记为 `timeout`。

**永不停止（NEVER STOP）：** 循环开始后，不要停下来问人类"要不要继续"。人类可能在睡觉。没有想法了就更努力地想：重读调研报告和失败想法表、把以前 `confirm_fail` 的近似成功组合起来、尝试更大胆的改动。直到人类手动停止你为止。
例外只有一个：runner 在连续 [12] 个候选或 [2] 个夜晚没有产生 `ESTABLISHED` 时会通知人类；人类会在本文件末尾的"当前方针"里写一段新的方向，你在下一轮读到后照做。

## 想法先验（按优先级；来自文献，详见 `README.md` 第 3、4 节）

| # | 在 `train.py` 里改什么 | 预期 | 依据 |
|---|---|---|---|
| 1 | 学习率扫描，LLM / 视觉-语言连接层 / ViT 分别设置；调度按训练进度比例 | +1~4 pp，便宜 | 已发表配方的学习率跨约 3 个数量级 |
| 2 | 真实裁剪图在混合中的比例：10% / 30% / 50% | 真实文献切片 +3~10 pp | 真实数据比例是文献中最大的单一杠杆 |
| 3 | 增强强度 + 由弱到强的课程（扫描噪声、模糊、JPEG、旋转、外文干扰、楔形键↔波浪键替换） | +3~8 pp | MolParser：40.1 → 69.5 → 76.9 |
| 4 | 标签"所见即所标"：图里画的是 Boc 就输出 Boc，由评测侧的固定缩写表展开 | 缩写切片大幅提升 | GTR-CoT；官方 MolScribe 在缩写集上 < 20%，用修正标签重训后 > 70% |
| 5 | 手性分子 2 倍过采样（Stereo-200k） | 手性切片 +2~5 pp | 手性是所有系统最弱的切片 |
| 6 | `max_pixels`：384² / 512² / 768²；保持长宽比的填充 | ±2~5 pp，成本随视觉 token 增长 | 每 32×32 像素一个视觉 token |
| 7 | LoRA 目标：仅注意力 / MLP gate+up / 全部线性层；rank 16~128 | +1~3 pp，遗忘更少 | 只训注意力：学到 +24.9、遗忘 −0.6 |
| 8 | EMA 或最后 k 个检查点平均 | +0.5~2 pp | speedrun 衍生项目中 EMA 贡献了约 63% 的收益；olmOCR 2 的权重平均 |
| 9 | 难例挖掘：上采样 S0 答错或多模型分歧（一致度 0.6~0.9）的样本 | +1~3 pp | MolParser 数据引擎 |
| 10 | 通用数据回放 5~30% | 守住探针护栏 | 防遗忘 |
| 11 | 最小风险训练（MRT），与 MLE 交替：N = 8~16，T = 0.5，奖励 = 0.1·valid + 0.5·sim·valid + 0.4·exact | 真实裁剪图 +3~10 pp | COMO：JPO +12.2、ACS +14.5，同数据纯 MLE 反而退化 |
| 12 | 先输出图遍历（原子/键）再给答案 | +2~3 pp，解码更慢 | GTR-CoT 消融 |
| 13 | 按 InChIKey 多数投票，k ≤ 8 | +1~4 pp，评测耗时 × k | MarkushGlyph MV@8 |
| 14 | SMILES 语法约束解码 | 降低无效率 | 约束解码 |
| 15 | 大分子（> 50 重原子）切块/第二视角 | 该切片 +3~10 pp | 大分子是公认短板 |
| 16 | GRPO/DAPO，二值"InChIKey 相同"奖励，只保留 rollout 有分歧的样本 | +2~8 pp，或精确匹配下降 | ChemVLR 正例；MolSeek-OCR 的 GSPO 反例 |

**已知的负面结果（不要重复踩坑）：**
- 直接对 OCR 型 VLM 做全参 SFT 曾经发散（MolSeek-OCR），先 LoRA 再选择性全参才稳定；
- Thinking 版本在 OCR 上比 Instruct 版本差；
- 不先 SFT 直接做 RL 几乎没有效果（ChemVLR：2.1 vs 92.7）；
- 奖励若偏重"图结构一致"而非精确匹配，会降低精确匹配（MolSeek-OCR 的 GSPO）——**奖励的等价定义必须和评测一致**；
- 任何 RL / MRT 改动都必须优于"同等 GPU 时长的继续 SFT"对照；
- 纯合成渲染数据迁移到真实文档很差；通用合成版面在有足够真实数据后是负收益。

## 数据与许可

- 本阶段只使用**商用轨道**的数据池（USPTO 专利附带的结构文件与图、PubChem/ChEMBL 渲染、CC BY 的 Markush 数据、Stereo-200k、PMC OA 商用子集、内部标注）。`prepare.py` 不会向 `load_pool()` 暴露研究轨道（非商用许可）的数据。
- 不要试图"还原"评测分子：任何从训练池生成的样本都会被比对评测集的 InChIKey 与骨架，命中的会被静默替换，你只会看到一个三档的拒绝比例。
- 需要新的数据源时，写到 `requests.md`，由人类决定。
